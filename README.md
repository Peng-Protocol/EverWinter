## Setup

Open any `.html` file directly in a browser. No build step, no server, no installation. Alpine.js and Bootstrap 5 are loaded from CDN — an internet connection is required on first load (cached after that).

To trade proactively, run `PseudoChaser` (longs only) with `MultiIndicator` and `Ashfall` loaded, or `PseudoWinter` (shorts only) with `MultiIndicator` and `Permafrost` loaded. To trade reactively, run `PsychoChaser` (longs only) or `PsychoWinter` (shorts only) on their own.

The Strategy Book explains how the Reactive and Proactive approaches differ, and the Psycho Handbook covers the Reactive bots' configs in depth.

## Menus

The UI has four views: **Market** (positions, scan controls, watchlist) plus three configuration/telemetry panels — **Config**, **Stats**, and **Trades**.

**Mobile** (≤768px): a bottom tab bar (⚙ Config · 📊 Market · 📈 Stats · 📌 Trades) switches between the four views full-screen, one at a time. Unchanged from earlier builds.

**Desktop**: Market, Config, Stats and Trades all sit side by side in normal document flow at the same level — no overlay, no dimming, no shadow. Config/Stats/Trades open via matching icon buttons (⚙ 📈 📌) in the topbar — no dedicated Market button, since it's never hidden. Config opens by default on launch; click its icon again (or any open panel's icon) to dismiss it.

Market is always twice as wide as one side panel. With both side panels open the split is Market 2/4, left panel 1/4, right panel 1/4; with one panel open it's roughly 2:1; with none, Market fills the row. Panels take slots in the order they're opened, not by which menu they are:
- First panel opened → left slot. Second → right slot.
- Once both slots are full, opening a third (currently-closed) panel replaces the **left** slot's occupant.
- Opening a fourth replaces the **right** slot's occupant — and it keeps alternating left/right on every subsequent replacement from there.

Two panels can be open at once; a third click always bumps whichever slot is due next rather than stacking a third panel.

## EverWinter / SunChaser (Live Trading Plugins)

EverWinter turns PseudoWinter into a live short-only Bybit bot; SunChaser does the same for PseudoChaser as long-only. Both sign requests with the stored `__ew_creds`/`__sc_creds` API key and place real orders — the topbar reads **Very Real Orders** once loaded, in place of the base simulation's **No Real Orders**.

- **Balance**: fetched automatically the moment a valid key/secret pair is saved in the credentials panel, not only at page load.
- **Symbol banning**: a symbol is banned for a week when Bybit reports it can't be traded, or when it's blocked until a trading agreement is signed (for example some leveraged or inverse instruments). Both cases need a manual fix on Bybit's side, so the ban is treated as long-term instead of retrying every cycle.
- **Post-bail re-check**: after a bail sweep (manual Danger Zone bail or an automatic Drawdown Throttle bail), the plugin queries the exchange directly for any position still open in its own direction (Sell for EverWinter, Buy for SunChaser) and force-flattens it with a direct reduceOnly market order. This catches positions that failed to fully fill.

## Main Config

Changes take effect immediately and are persisted to localStorage automatically.

| Setting | What it does |
|---|---|
| **Scan Interval** (`scanMins`) | How often (minutes) the bot runs a full market scan. Controls both entry frequency and the scan bar in the UI. |
| **Max Positions** (`maxPos`) | Maximum simultaneously open positions. No new entries open once this is reached. |
| **Leverage** (`leverage`) | Position leverage. Affects order size, TP/SL prices, and EDa thresholds. |
| **Min Notional** (`minNotional`) | Base margin per position in USDT. Actual order size = minNotional × leverage. |
| **Entry TP** (`entryTpRoi`, default 50%) | Take-profit ROI % target. When EDa is active this is the buffered target — the debt-free close happens at a lower percentage. In DCA Mode this is also the base the per-stage TP ladder scales down from (entry TP ÷ (stage+1), min 3%). |
| **Binary Mode** (`binaryModeEnabled`) | On: every position gets a take-profit and a stop-loss at entry and no DCA adds (`binaryTpPct`/`binarySlPct`, both default 50%). Off: multi-stage DCA. Add orders trigger below entry (PseudoChaser) or above it (PseudoWinter), each with a lower TP ROI target, and the stop-loss (`dcaSlPct`, default 16%) only arms once every first-wind DCA stage has filled. The DCA config controls need the `dca-long`/`dca-short` plugin (`plugins/modes/`); the binary and DCA logic itself is in the base bot either way. |
| **DCA Stages** (`dcaStages`, default 1) | Number of DCA add orders (1–6 in the plugin slider). Each stage has its own trigger slider (`dcaAddPct1`…`dcaAddPct6`, defaults 3 / 6 / 12 / 18 / 24 / 30), set as % below entry for PseudoChaser or above entry for PseudoWinter, and only the sliders for selected stages appear. Triggers always increase by stage: lowering one stops at the previous stage's trigger, and raising one pushes the later stages up. Configs saved before per-stage triggers (a fixed 1.5%, then +3% per stage for non-3 stage counts) are migrated on load/import so they keep the same trigger prices. |
| **DCA Add Notional** (`addNotional`) | Margin (USDT) added per DCA stage — separate from **Min Notional**, which only sizes the initial entry. |
| **Drawdown Throttle** (`drawdownThrottleEnabled`) | Halts new entries for `drawdownHaltHours` (default 12h, free-entry field with no upper bound) when the rolling 6h realized PnL falls below a loss threshold. The Halt tab shows the live 6h rolling PnL. Its **Clear 6hr Record** button (with confirmation) zeroes that window manually, whether or not a halt is active. |
| **Drawdown Factor** (`drawdownThrottleFactor`) | Loss threshold as a multiple of entry margin. At 0.5× with $1 margin, $0.50 of rolling losses triggers the halt. |
| **Bail on Trigger** (`drawdownBailEnabled`, default on) | When on, triggering the Drawdown Throttle halt also immediately closes every open position at market (`bailAll()`) — the same sweep the Danger Zone's manual **Bail All Positions** button runs, and what the **BAIL** trade-card badge marks. |
| **Gains Lock** (`gainsLockEnabled`) | Halts new entries for 12 hours once rolling 6h profit hits a target. Banks a winning streak before it reverses. Same 6h rolling PnL readout and **Clear 6hr Record** button as Drawdown Throttle, shown in its own section of the Halt tab. |
| **Gains Factor** (`gainsLockFactor`) | Profit target as a multiple of entry margin. Same scale as Drawdown Factor. |
| **Manual Halt** | Button (Halt tab) that blocks all new position entry indefinitely until manually lifted. Independent of Drawdown Throttle and Gains Lock — overrides both and doesn't stack with either. |
| **EDa / Laggard Check** (`laggardCheckEnabled`) | Enables the Effective Debt Adjusted system. Realized losses are passed forward to surviving positions, which take higher TP targets to recover the debt. **Requires the EDa-Winter / EDa-Chaser plugin** (`plugins/modes/`). |
| **TP Buffer** (`laggardProfitOffset`) | Extra TP headroom reserved above the functional target (%). The debt-free close happens at `tpPct ÷ (1 + buffer/100)` — at 50% buffer with an 18% TP slider, trades close at 12% without debt. Requires the EDa plugin. |
| **Ticker Cooldown** (`bulkTickerCooldownHours`) | How long the bot reuses a cached bulk ticker fetch before hitting the API again (default 12h). The bulk list only says which symbols exist — criteria data never reads it — and the same window sets how long MIW/MIC's re-entry block and the Ticker Graylist hold a closed symbol. |
| **Whiplash Audit** (`whiplashEnabled`) | When on, the position watcher fetches 1-minute klines near TP to confirm whether price spiked through TP between watcher cycles. |
| **Whiplash Proximity** (`whiplashProximityPct`) | How close (%) to TP price triggers the kline audit. |
| **Runtime Limit** (`runtimeHours`) | Maximum position age. Forces a close at the deadline if TP hasn't been hit. |
| **Symbol Banlist** (`banlistEnabled`) | When on, symbols on the ban list are excluded from all scans. Entries expire after 7 days. |
| **Position Price Feed** (`restPollEnabled`) | When on, replaces the WebSocket price stream for open positions with periodic REST API calls. Use if the WS feed returns stale or incorrect prices. |
| **Price Poll Interval** (`restPollBaseSec`) | Base polling interval in seconds for REST mode. The interval doubles automatically when price moves less than 0.1% between ticks and resets to base on any meaningful move. |
| **Dispatch Every** (`schedIntervalMs`) | Minimum gap (ms, default 150) between successive background fetches dispatched from the scheduling queue. Lower = faster background data turnover, at the cost of more simultaneous requests. |
| **Max Concurrent** (`schedMaxConcurrent`) | Hard cap (default 4) on background fetches in flight at once, regardless of how many subsystems have work queued. |
| **Slice Budget** (`schedSliceMs`) | How long (ms, default 8, 2–30) a scan stage runs before handing the browser back; a hidden tab uses 40 ms. Lower = smoother page, slightly slower scans. |
| **Follow Partner Bot** (`lfFollowPartner`) | When on, this bot stops fetching bulk tickers itself and uses the partner's shared cache. The partner needs no toggle: it acts as leader while its heartbeat (written once per completed scan cycle) is fresh, meaning newer than 2× **Scan Interval**. If the partner goes stale, this bot resumes scanning on its own, and it steps back down as soon as the partner returns. It also won't open a position on any ticker the leader already holds, checked at entry before any instrument or price lookups. Permafrost/Ashfall ignore this setting and always sample independently. |
| **Config Lock** (`cfgLocked`) | Locks all config controls to prevent accidental changes while the bot is running. |

## Stats Menu

The stats panel shows session-level metrics since the page was last loaded or state was cleared.

| Stat | Meaning |
|---|---|
| **Session PnL** | Cumulative realized PnL from all closed trades this session. |
| **Win / Loss** | Count of profitable vs. losing closed trades. |
| **Win Skew** | Share of total PnL magnitude (all closed trades, cumulative) that came from wins — sum of winning PnL ÷ (sum of winning PnL + sum of losing PnL). Weighted by trade size, not just a count of wins vs. losses. |
| **Avg PnL** | Mean realized PnL per closed trade. |
| **Open uPnL** | Unrealized PnL across all currently open positions. |
| **Positions** | Count of open positions. |
| **Last Scan** | Timestamp of the most recent scan cycle. |
| **Laggard** | The oldest open position — the EDa debt holder. Shows its current debt load when EDa is active. |
| **Persistence** | "Active" (live in-memory position count) vs. "Stored" (confirmed saved to localStorage). These should always match. |

**Persistence mismatch**: shown in red with a warning banner. It means a save failed or was overwritten, and usually clears on its own within a few seconds as the bot retries automatically. If it doesn't:
- Check the activity log for `[PST]`/`[PERSIST]` entries.
- Close any duplicate tabs of the same bot — a second tab can overwrite the first tab's saves with its own stale position count.

**Storage usage** (dropdown below Persistence, PseudoWinter/PseudoChaser only): breaks this bot's localStorage footprint down to one row per data type, including genuinely shared cross-bot keys but never the partner's private state. Oversized rows show in red with a **✕** to clear that bucket (with confirmation), and **Export** downloads the breakdown as a text file.

**Power usage** (dropdown below Storage usage): a rolling average and peak of how many milliseconds the app spends reacting each second. A rising figure usually means a plugin panel left open somewhere is doing more work than it needs to — closing analytics panels you're not actively watching brings it back down.

**Ticker Graylist**: when MultiIndicator is enabled, the Stats menu shows a Ticker Graylist section listing symbols currently blocked from re-entry. It's empty when nothing is blocked. Each listed symbol clears itself automatically once the bulk ticker cooldown window elapses — no manual action needed.

### Actions Dropdown

- **Export** — Downloads current bot state (config, positions, closed trades, ban list, EDa state) as a `.json` file. Plugins with their own data (Permafrost/Ashfall profile, scorecard) have separate Export buttons inside their own accordions — the Stats menu Export covers the base bot state only.
- **Import** — Restores state from a previously exported `.json` file. Config fields merge field by field, while positions are replaced wholesale. A 5s debounce prevents accidental double-imports. Config keys that no longer belong to a loaded feature (the bot or an installed plugin) are dropped on import and on every save, so retired settings don't linger.
- **Clear Closed Trades** — Wipes the closed trades list, resets session stats, and clears the 6hr drawdown/gains-lock rolling PnL windows. Open positions are unaffected.
- **Clear All** — Full reset. All positions, trades, stats, and config are wiped (config reverts to defaults).

### Activity Log

Timestamped entries for every significant bot event. Color coding:

- **White** — informational (scan results, entries, closes)
- **Yellow** — warnings (halts engaged, API retries)
- **Red** — errors (API failures, plugin conflicts)

Common prefixes: `[MHL]` manual halt · `[DWN]` drawdown throttle · `[GLK]` gains lock · `[PST]` (PseudoWinter) / `[PERSIST]` (PseudoChaser) save failures or recovered positions · `[PFR]`/`[ASH]` climate plugin events · `[MIW]`/`[MIC]` multi-indicator events.

The log keeps the latest 300 entries in memory and in localStorage, dropping the oldest first. Each entry has a local `HH:MM:SS` string (`t`), which is what the UI shows, and an epoch-millisecond timestamp (`ts`). `ts` lets you match a log export to position and config exports, which are timestamped in UTC epoch; `t` alone can't be tied to a date or time zone.

## Trades Menu

The trades panel shows a card for each closed trade, newest first, with a close-reason badge: **TP**, **SL**, **FORCE** (runtime limit), **BAIL** (drawdown throttle bail, which closes every open position immediately on both bots), **Sub** (closed to free a slot for a higher-ranked candidate via MIW/MIC Substitution) or **Eject** (closed by MIW/MIC Ejection when two or more Deferment paths are active at once). Reasons added by other plugins show their own label, or the raw reason name if none is registered. On EverWinter/SunChaser, a bail sweep is followed by a direct exchange re-check.

**Roll-up card**: when the closed trades list exceeds 50 entries, the oldest are compacted into a single roll-up card showing their net PnL, trade count, and the date range they cover. The roll-up is not a trade — it is a historical summary. In the PnL chart, the roll-up's net value acts as a baseline offset applied to every plotted point.

**PnL chart**: click the **PNL CHART** bar below the header to expand a cumulative PnL line chart. The X-axis spans from the first to the last individual closed trade at fixed spacing. The chart is green when the net result is positive, red when negative. The chart only appears once at least 2 individual trades are closed.

**CLEAR button**: removes all closed trades, resets session stats, and clears the 6hr drawdown/gains-lock rolling PnL windows. Clicking CLEAR reveals an inline confirmation ("Sure? Yes / No") before anything is deleted. Yes confirms; No cancels with no change.

## MultiIndicator Plugin (MIW / MIC)

The Multi-Indicator plugin filters entries with combinations of criteria called **slots**. A slot is an AND-gate: every criterion in it must be true for a ticker to qualify, and a ticker only needs to match one slot to be eligible for entry. No criterion is mandatory; a slot (Auto or manual) can use any combination of `fund`, `va`, `ioa`, `lta` and `lpa`. Entry is scan-driven only: one pass per fresh sample batch.

### Criteria

See StrategyBook's **Market Reading** section for what each criterion means and when to use it. This section covers tiering, recording, and fetch mechanics only.

**Slot builder badge key**: the manual slot builder uses the same emoji set as position/trade badges.

| Badge | Criterion |
|---|---|
| 🤑/💸 | Funding tier (direction-aware, see [Trivia](#trivia). |
| 🔊 | V/A, volume versus the population sample-window average. |
| 🎲 | IO/A, open interest versus the population sample-window average. |
| 🕐 | LTA, last completed hour's turnover versus the ticker's own average hour. |
| 💹 | LPA, last completed hour's price change versus every other ticker in the sample window. |

**Recording**: every criterion is recorded as a signed tier on the position at entry.

### Config

| Setting | What it does |
|---|---|
| **Enabled** (`miwEnabled`/`micEnabled`) | Master on/off. When off, the plugin opens no entries and runs no exits. |
| **Picks** (`miwPicks`/`micPicks`) | Max new entries per scan cycle (1–10). |
| **Share Cap** (`miwShareCapEnabled`/`micShareCapEnabled`) | Limits plugin entries to a percentage of `maxPos`. Prevents MIW/MIC from filling all position slots. |
| **Share Cap %** (`miwShareCapPct`/`micShareCapPct`) | The cap percentage. At 50% with maxPos=6, MIW/MIC can hold at most 3 positions. |
| **Tier Step Sizes** (`miwFundStep`/`miwVaStep`/`miwIoaStep`/`miwLtaStep`/`miwLpaStep` and `mic` equivalents) | Read-only chips on the **Fetch** tab showing the tier step for each criterion. Defaults: `va` and `ioa` 1% deviation from the population average; `lta` 10% deviation from the ticker's own hourly average; `lpa` 0.25 absolute points of 1h price change (shown as `pp`); `fund` 0.0025% of funding rate per tier, so 0.25% is tier 100. They can't be edited from the UI; change them via config import. Older installs saved the fund step as 0.25; it's migrated once, and saved `fund>N`/`fund<N` slot gates are rescaled ×100 so each keeps its threshold. |
| **Cascade** (`miwCascadeEnabled`/`micCascadeEnabled`) | Closes every open position, whichever strategy opened it, when their collective unrealized profit reaches a threshold, banking a group move before it reverses. The position watcher checks this every 5s while the bot runs, not just once per scan, so a threshold crossed and reversed between scans is still caught. |
| **Cascade %** (`miwCascadePct`/`micCascadePct`) | Collective uPnL trigger as a % of base margin (minNotional ÷ leverage). While **Target Halving** is on the slider is hidden and this value is the ceiling. |
| **Sacrifice** (`miwSacrificeEnabled`/`micSacrificeEnabled`) | Closes every open position, whichever strategy opened it, when their collective unrealized loss reaches a threshold, capping group drawdown. It uses the same continuous position-watcher check as Cascade. |
| **Sacrifice %** (`miwSacrificePct`/`micSacrificePct`) | Collective uLoss trigger as a % of base margin (minNotional ÷ leverage). While **Target Halving** is on the slider is hidden and this value is the ceiling. |
| **Target Halving** (`miwTargetHalvingEnabled`/`micTargetHalvingEnabled`, default on) | Sub-toggle on the **Exit** tab, shown only while Cascade or Sacrifice is on. It scales each new position's entry TP and SL, and the Cascade and Sacrifice %, by the Sample Scorer's headline relative to its recorded peak (see **Sample Scorer** below): full configured values at the peak, zero at an even share or below. While it's on, the Cascade/Sacrifice sliders are hidden and act as ceilings, and a read-only line under the toggle shows the live resolved targets. It also drives Deferment. It needs Sample Scoring; without that, or before a scorecard value and peak exist, it does nothing and the configured values apply. |
| **Min Entry TP** (`miwMinEntryTp`/`micMinEntryTp`, default **6**) | Shown only while Target Halving is on. This is the ROI % below which a position can't cover its entry and exit fees. If the resolved entry TP (or the resolved Cascade target, while Cascade is on) falls under it, the market isn't worth trading and new entries are deferred. Cascade and Sacrifice also never fire below it, or below 1%. |
| **Substitution** (`miwSubstitutionEnabled`/`micSubstitutionEnabled`) | When no entry slot is free (maxPos or Share Cap reached), closes the worst-scoring held position (any strategy's, not only MIW/MIC's) and opens the best fresh candidate in its place, but only if the candidate's collapsed score beats the held position's *current* score by the **Substitution Margin**. A held MIW/MIC position's current score (`_miwLiveCompositeScore`/`_micLiveCompositeScore`) is recomputed live from its rolling-average criteria (see **Position Rolling Average**), so it's judged on where it has drifted to, not where it stood at entry. Each candidate is pre-flighted through the Force-Evaluate top-up and entry vetoes before anything is closed, and a blocked one falls through to the next. It requires Co-Qualifying Penalty (Permafrost/Ashfall); without it every score is 0 and Substitution never fires. |
| **Substitution Margin** (`miwSubstitutionMarginPct`/`micSubstitutionMarginPct`) | How much better the new candidate must score than the worst held position, as a % of base margin (minNotional ÷ leverage), before a swap happens. Prevents swapping on marginal score differences. |
| **Substitution Min Age** (`miwSubstitutionMinAgeMins`/`micSubstitutionMinAgeMins`, default 35) | Minimum minutes a position must be held before it becomes eligible to be substituted out. |
| **Deferment** (`miwDefermentEnabled`/`micDefermentEnabled`, default on) | A regime-proxy entry stop, set on the **Exit** tab below Substitution. It blocks every new entry while the Sample Scorer headline is below zero (the favored side's mean raw 1h move in the bot's favor), or while a clause is in effect: **Both Poles Red** or the **Target Halving** floor. It needs Sample Scoring for the headline. Two or more active paths trigger Ejection (see **Deferment & Ejection** below). |
| **Both Poles Red** (`miwDeferBothRedEnabled`/`micDeferBothRedEnabled`, default off) | Sub-toggle, only shown while Deferment is on. Defers while any criterion has both its `+` and `-` pole in the red on the scorecard side the chart shows — no good pole left to enter on. A pole under Min Samples doesn't count. Counts as one path toward Ejection. |
| **Re-entry Block Mode** (`miwReentryBlockMode`/`micReentryBlockMode`) | Defaults to **Losers Only**, which lets a symbol that just closed in profit re-trigger immediately and blocks only a symbol that closed at a loss. **Winners + Losers** blocks a symbol from re-triggering for one bulk-ticker cooldown window (12h by default) after any close, win or loss. |
| **Auto Slots** (`miwAutoSlots`/`micAutoSlots`) | Replaces the manual slot list with a minimum-gate qualifier: a ticker qualifies once it satisfies at least **Minimum Criteria per Slot** non-excluded criteria — not a fixed-size combination. Every criterion the ticker actually satisfies is captured and scored, not just enough to clear the floor. See `_miwAutoQualify`/`_micAutoQualify`. |
| **Minimum Criteria per Slot** (`miwAutoSlotSize`/`micAutoSlotSize`) | The floor (1–5). At 1, a single true criterion qualifies the ticker — any others it happens to satisfy are still captured and scored. |
| **Exclude from Auto** (`miwAutoSlotExclude`/`micAutoSlotExclude`) | Criteria omitted from Auto's qualifying set entirely — never checked, never counted toward the minimum, never scored. Excluding more than `5 − Minimum Criteria per Slot` leaves Auto unable to ever reach its floor, and the plugin reports no active entry gate (`_miwAutoActive`/`_micAutoActive`). |
| **Force-Evaluate General Criteria** (`miwForceGeneralCriteria`/`micForceGeneralCriteria`, on by default) | Auto mode only. A ticker can miss `fund`, `lta`/`lpa` or `ioa` simply because that cycle's capped sample hadn't reached it yet. When on, just before a ticker opens, the plugin (`_miwTopUpGeneralCriteria`/`_micTopUpGeneralCriteria`) re-checks those criteria with a forced per-symbol fetch, adds any that are newly true and recomputes the composite score. It never drops a criterion already found, and the Lukewarm Veto is re-checked against the topped-up criteria before the open goes through. On a following bot this is the one exception to the no-own-fetch rule: it uses the leader's shared OC cache first and fetches the single symbol only if that has nothing. It costs a few extra requests per entry. |
| **Pole Blocking** (`miwPoleBlockEnabled`/`micPoleBlockEnabled`, default on; `miwPoleBlockPct`/`micPoleBlockPct`, default **200**) | Entry-tab toggle with a Threshold % field, shown only while Sample Scoring is on. It blocks a candidate that carries a dial pole whose scorecard edge is zero or negative and trails its positive partner pole by at least the threshold. The gap is `(partner − pole) / min(\|pole\|, partner)`, so LTA- at −0.20pp against LTA+ at +0.05pp is a 500% gap and never opens. There's no magnitude floor, both poles need Min Samples, a non-positive partner is left to Both Poles Red, and it reads the favored side. Blocks count in the scan skip summary and log a `🚧 Pole Blocking` line. |
| **Sparsity** (`pfSparsePct`/`afSparsePct`, always on, no toggle; default **25**, config-only) | Entry candidates are ranked by how much sample data their criteria have: each matched pole's score is pulled toward zero when its sample count is small. A candidate whose thinnest pole holds less than the floor % of the median sample count for its bucket type (Extreme or Lukewarm) is not entered. A family the scorecard doesn't score at all (LPA, under Sample Scoring) is skipped rather than read as an empty pole, so it can never block an entry. Blocks count in the scan skip summary and log a `🪶 Sparsity` line. |

### Slots UI

**Manual mode**: click a slot to select it, then toggle criteria on/off in the picker row below. ✕ deletes the slot; `+` adds a new empty one. All five criteria are tiered — clicking one opens its gate picker (direction plus tier) rather than toggling a bare tag. A slot with no criteria in it never matches.

**Auto mode**: replaces the manual builder with a minimum-slider and an exclusion chip row. A ticker qualifies on at least the chosen minimum of non-excluded criteria — every criterion actually true is scored, not just enough to clear the floor. The hint under the slider states the current floor as "qualifies on any N of M secondary criteria."

The five criteria are independent signed tiers, so any subset can be true for the same ticker at once and each contributes to the qualifying count on its own.

## Permafrost / Ashfall Plugin

Permafrost targets PseudoWinter; Ashfall targets PseudoChaser. They provide two things: the **Extremity Scorer / Lukewarm Scoring** engine that decides which readings MIW/MIC may trade on, and the **cross-bot bus** that lets the two sides coordinate halts. The bots' own halt timers govern halts; the plugins only lift them (Mutual DDH Lift) or trigger them (Gains Continuation). The panel has two tabs, **CROSS** and **SCORE**, with the Danger Zone (Export / Import / Clear Profile / Clear Plugin State) below.

### Config

| Setting | What it does |
|---|---|
| **Permafrost / Ashfall Mode** (`permafrostEnabled`/`ashfallEnabled`) | Master toggle. |
| **Cross Broadcast** (`permafrostCrossEnabled`/`ashfallCrossEnabled`) | Always on, no toggle. It writes cascade/sacrifice triggers, drawdown halt and gains-lock transitions, and GC steps to a shared log (`__everwinter_cross_v1`, retained 30d) that the partner bot reads; Mutual DDH Lift and Gains Continuation depend on it. Cascade/sacrifice is logged once per collective-exit trigger, not once per position closed, tagged with the position count and collective PnL when it fired; plain individual TP/SL closes aren't broadcast. On page load into an already-active halt, the plugin backfills the halt-start marker (timestamped to the halt's real start) if the bus doesn't already show it, so Mutual DDH Lift still sees the halt's true age. |
| **Mutual DDH Lift** (`permafrostMutualDdLiftEnabled`/`ashfallMutualDdLiftEnabled`) | When both bots are in drawdown halt or gains lock at the same time, lifts the side whose halt started *earlier*. The newer halt stays, since it hasn't had any cool-down yet and the older one already has. It's checked every 15 s and depends on each bot's halt-start marker being on the shared bus (see the reload backfill note above). |

### Partner Feed

The Cross tab shows a scrollable **Partner Feed** listing the last 20 events the partner bot has broadcast: cascade/sacrifice triggers, DDH start/lift, gains-lock start/lift, and GC steps. Each row shows a kind-specific detail — position count and collective PnL for cascade/sacrifice, PnL and step number for GC, symbol for a rolling sacrifice — and a UTC timestamp, date-prefixed for anything not from today. Empty until the partner has broadcast at least one matching event.

Useful for diagnosing Mutual DDH Lift and GC: if the feed shows a partner `ddh-start` or `gc` step but no lift follows on this bot, the problem is on the receive side (freshness window, own-side toggle, read loop), not the trigger.

### Sample Chart

Below the Score tab's scoreboard is a per-ticker bar chart of the sample cycle history, scrollable through past cycles. Two header buttons step through the views **Vol → IO → Fund → LTA → LPA**, plus **Liq** while Liquidation Surveillance is on and **Per** while Period Scorer is on. Each button is labelled with the view it goes to, the order wraps at either end, and the view resets to Vol on reload. The chart only shows when at least one sample exists. Each cycle group is stamped with its sample time: click one to pin the summary and chips to that cycle, or click elsewhere to return to the latest.

- **Vol** / **IO**: the 24h-turnover and open-interest samples, with a **Total avg** (the number `va`/`ioa` measure against, plus ticker count) above a **Batch avg**. No outlier cap.
- **Fund**: each sampled ticker's funding rate (%), signed, with a **Total avg** and **Batch avg** like Vol/IO. Funding rides in the sample records, read from each ticker's fresh fetch.
- **LTA** / **LPA**: signed views (turnover deviation %, 1h price change %) drawn up or down from a zero line, on a symmetric axis sized to 1.3× the 95th percentile of |value|. Only tickers with a candle reading in a cycle appear. **LPA** also shows a **Silence** line with two figures. Batch silence compares this cycle's spikiness (the average distance of its tickers from the window average) with the historical bottom and peak, where 100% is as quiet as it has ever been; window silence is the same for the mean spikiness of the window's batches. It's display only, and the Silence Amplifier doesn't read it.
- **Per** (while Period Scorer is on): the period forecast. It's the one view not aligned in time with the others, because its newest column is always a full slice of batches ahead of them. Each column is one projected batch (the last four forecasts), with one bar per data type in that type's colour (the same colours as the other views), drawn in standard deviations from its own window average (±3 shown) up or down from a zero line, so all five types share one axis. A closed batch shows what actually happened as the bar and the estimate as a white tick; batches still to come are the forecast itself, drawn desaturated. Click a column to select it (the latest closed batch is selected by default). The summary shows batches stored, slice and state (building, grading, under the floor, or scoring), a **Window accuracy** line (overall and per data type), a **Batch accuracy** line for the selected batch (overall and per data type, or pending if it hasn't closed) and a **Criteria** pill that opens a table of that batch's estimate and actual per criterion.
- **Liq**: each watched ticker's liquidation lean in pp over the watch that started on that cycle, shown as a signed view from a zero line (up = liquidated shorts dominated, down = liquidated longs, zero = watched but quiet). A **Window avg liquidation lean** (each watched ticker's latest reading, quiet ones at 0) sits above the **Batch avg**. The **Tickers** pills list only tickers that had liquidation events in the displayed batch, and their style shows how one-sided the watch was and which side led: **favorable** (pure, the bot's side) has fill and outline, **mixed favorable** fill only, **mixed unfavorable** outline only, **unfavorable** neither. Mixed means the minority side holds more than **Mixed %** of the turnover (default 30%; a dead-even split counts as mixed unfavorable), and favorable is liquidated shorts on Chaser and liquidated longs on Winter. Hovering shows the short/long split and the ticker's window instability, a `!` marks tickers currently skipped for entry, and the summary line adds how many tickers are unstable. Watches from before the split was recorded only know which side led, so their pills show as pure. Only tickers watched in a cycle appear, and only cycles watched while Liquidation Surveillance was on carry it; the newest cycle fills in once its watch is scored on the next scan. It rides in the same cycle history as the other views, so it holds as many cycles as that history does.

### Extremity Scorer

Each criterion is a **dial family** (`fund`, `va`, `ioa`, `lta`, `lpa`) with a `+` and a `-` pole; under Sample Scoring `lpa` is the outcome and has no dial. Each scan's readings build per-pole cutoffs that sort every reading as extreme or lukewarm, and closed trades are tallied per side and per pole. The side that has earned more dollars becomes the favored side (ties default to extreme), and the Lukewarm Veto rejects candidates whose criteria mostly sit on the other side. Scorecards are per bot, each reflecting only its own trades; see **Extremity Scorer Internals** in Trivia.

**Scorecard chart**: only the favored side's chart is shown — Extreme or Lukewarm — and it flips automatically when the favored side changes. It is a single non-wrapping row of criterion duos that scales to its container: the left bar is the `+` pole, the right bar the `-` pole, profit rises above a zero line and loss hangs below it, and the criterion emoji sits underneath. The header shows the side's name and total; hover a bar for its PnL and W/L. Only shown when MIW/MIC (or Blind-Entry / Liquid-Diver) is loaded and enabled.

**CLEAR** wipes this bot's closed-record store, sample pool, Sample Scoring store and Period Scorer store together (`__ew_pf_extremity_v1`/`__ew_pf_dialpool_v1`/`__ew_pf_sampleobs_v1`/`__ew_pf_period_v1`, or the `af` set) — cutoffs included, never the partner's.

Under **Sample Scoring** the same chart is titled **Sample Scorer** and its bars are mean edge in pp, with liquidation outcomes blended in when Liquidation Surveillance is on (hover shows the average edge, ↑/↓ counts and n). A status line above it shows the scored-sample count. The LPA dial isn't drawn, since LPA is the price outcome, unless Liquidation Surveillance is on, when LPA is scored on liquidation outcomes and drawn. With Liquidation Surveillance on, the status line also shows the liquidation-sample count, the tickers on watch and how many are on the quiet graylist.

**Headline & gauge**: the header number is relative. It's the favored side's favorable share of raw 1h move, meaning the move in the bot's favor as a share of all raw move on that side, so 50% is even. A gauge under it is scaled to the best share recorded, and hovering shows the sample count, the mean in dollars on one base position and the relative edge. The per-criterion bars stay relative (mean edge vs the sampled population). Beneath the gauge, **bottom** and **peak** show the lowest and highest share recorded; they only update once the favored side has at least 10 raw samples (and at least Min Samples), and they're cleared with the samples. The headline reads `—` until enough samples carry a raw move. With Liquidation Surveillance on, the share and the dollar mean are the 50/50 mix of the price and liquidation values (hover shows how many liquidation samples went in), and **bottom** and **peak** record that mixed share.

## Randomized Outcomes

Scan timing drifts independently per tab, and the sample is a fresh random draw of **Batch Size** candidates each cycle, so two identically configured instances won't share entry triggers, exit timing, or readings. This is intentional: instances in lockstep are easier to front-run and cluster losses at the same market event.

## Multiplex Plugins

To save resources in single-file browser execution, the system supports **Multiplex Plugins**. A standard plugin keeps its own telemetry isolated. A multiplex plugin instead hooks into the combined component built when all plugins are loaded, reading the core data arrays, batched API payloads and state structures directly, without wrapping or reassigning parent methods. This treats the master surveillance/execution engine as a shared database, which cuts resource use and avoids race conditions between plugins.

### The Speeder Module (Tentative Multiplex)

Located in `/plugins/multiplex/`, **Speeder** reuses functions in `MultiIndicator` and the data produced by `Ashfall/Permafrost`. That lets it read the rolling sample-cycle histories and the entry criteria builder directly.

* **What it does**: instead of judging order flow by fixed millisecond limits, Speeder splits the whole deduplicated pool of recent per-ticker trade intervals at the median on each scan.

* **How it does it**: to filter noise, landing in the fast or slow half isn't enough. A ticker's trade interval must also pass that half's own *mean*, which confirms a clear gap from baseline market speed.

* **When it acts**: like `MultiIndicator`, Speeder chooses its entry criteria (fast or slow) automatically, using a `base` setting tied to the liquidation regime. It can enter fast or slow tickers in hot or cold regimes.

* **When it doesn't**: if the surveillance plugins it depends on aren't in the combined component, Speeder logs a warning and stays inactive.

> **Note**: The Speeder strategy is tentative and lacks long-term historical validation; it remains isolated within the multiplex directory for demonstration purposes and architectural testing.

### Criteria Sampling Internals

- **Ticker Ranking**: each scan draws **Batch Size** tickers (default 50) at random and fetches their data fresh; that batch is the sample that feeds scoring. Entry candidates are ranked on every ticker's latest stored reading, however old, and each is refetched right before it opens, so any ticker the sample has reached can be picked. Refetches stop at one batch size per scan, since fetching all five criteria across 600+ tickers every 10-minute scan would be too heavy on computation and bandwidth; a larger batch size is an option if you have the resources. The batch isn't always purely random: with Liquidation Surveillance on, tickers that just had liquidations stay and quiet ones are replaced (see **Liquidation Surveillance** below), and with the Silence Amplifier on, up to its reserved share goes to noisy tickers first (see **Silence Amplifier** below).

- **Tier gate**: every criterion computes an integer tier as `floor(value / step)` and compares it against N. `fund` truncates toward zero instead, so a tiny negative rate lands on `fund-0` (mirroring `fund+0`) rather than flooring to `fund-1`. Current step sizes show as read-only chips under **Tier Step Sizes** on the Fetch tab. The same tier is recorded on the position and used as the scorecard key, so `fund>40` and `fund+70` are different tiers and are scored separately.

- **Bare-form exception — `fund`**: in Auto mode, a criterion named without a `>`/`<` comparison normally still requires a nonzero tier. `fund`'s bare form is the exception: it matches any finite funding rate, exactly 0% included, because real Bybit funding rates mostly sit well under a single **Fund Step**. A near-zero rate is a real lukewarm reading (`fund+0`/`fund-0`), so it attaches and feeds the lukewarm chart. The tiered forms are unaffected.

- **Funding emoji**: position and trade badges show 🤑 or 💸 for a `fund` tier, and the emoji says whether that funding sign favors the bot's own direction, so Winter and Chaser show opposite emoji for the same raw sign. The Extremity Scorer's own pills use one fixed set on both bots (💸 positive, 🤑 negative).
- **`va` / `ioa`**: `va+12` = 12 tiers hotter than the sampled population. `_pfVolIoWindowAvg`/`_afVolIoWindowAvg` delegates to `_pfWindowStats`/`_afWindowStats`, a deduplicated latest-reading-per-symbol read (`vol`, `oi`, `lta` or `lpa`) memoized per history state; the Sample Chart's Total avg draws from the same read.
- **`fund`**: tier is `trunc(rate% / Fund Step)` with an explicit sign, so tiny negatives tag `fund-0` and exact zero tags `fund+0`. Sample records carry the funding rate as `fr` (%) so the Fund chart and Sample Scoring can use it.
- **`lta`**: `_pfLtaDev`/`_afLtaDev`; `lta+12` = 12 × **LTA Step** (default 10%) above the ticker's own average hour (`turnover24h / 24`). No population baseline.
- **`lpa`**: `_pfLpaWindowAvg(sym)`/`_afLpaWindowAvg(sym)`, in tiers of **LPA Step** (default 0.25pp). Absolute points, since a relative deviation is unstable near a zero mean. No tier until at least one other ticker has an `hc` reading in the window.
- **Candle fetch**: `_pfHourCandle`/`_afHourCandle` calls `GET /v5/market/kline` at `interval=60&limit=3` and takes the row whose start is the last completed hour (`_pfHourStart`); the forming candle is never used. Results sit in a memory-only per-symbol cache (`HOUR_CACHE`, pruned past 500). Each batch attaches `ht` and `hc` to the ticker's OC cycle entry, so a **Follow Partner Bot** instance gets them from the leader (`_pfHourReading`/`_afHourReading`). The fetch rides the same batch (`wantHr` on `_ocFetchBatch`) whenever `lta` or `lpa` is in use.
- **Fresh batch fetch**: `_pfFetchFreshTicker`/`_afFetchFreshTicker` calls `GET /v5/market/tickers?category=linear&symbol=` per batch symbol, keeps the raw payload for the scan (`_pfFreshTicker`/`_afFreshTicker`) and stores a compact `{ vol, oi, fr, px, ch }` reading. A failed fetch drops the ticker; there is no fallback to the bulk list. A **Follow Partner Bot** instance rebuilds tickers from the leader's readings (`_pfSynthTicker`/`_afSynthTicker`). Entry candidates are refetched the same way by `_pfFetchCandidate`/`_afFetchCandidate` (ticker, plus OC and the hour candle when used), which touches neither the OC results nor the cycle history.
- **Entry-pool freshness**: MIW/MIC act once per new batch (`_pfOcResultsAt`/`_afOcResultsAt`), not once per bulk fetch, and `_miwOpen`/`_micOpen` skip the pre-open price refetch for a ticker from the current batch (`_pfTickerIsCurrent`/`_afTickerIsCurrent`). Candidates are ranked on each ticker's latest stored reading (`_pfLatestReadings`/`_afLatestReadings`, rebuilt by `_pfSynthStored`/`_afSynthStored` with `_cycle` set to that reading's own cycle time, so only the latest batch counts as current). Before a non-batch candidate opens or displaces a position, `_miwVerify`/`_micVerify` refetches it, reruns the slot match and veto with the dial-pool sample off, and stops at **Batch Size** refetches per scan. The refetched ticker only has to still qualify; it doesn't need to keep its ranked tier or score.
- `_miwHourTier`/`_micHourTier` returns `null` for missing data: the criterion check reads it as false and the annotator as "no sample", never a fake `+0`.
- Emoji for retired criteria stay resolvable in `critEmoji`/`afCritEmoji` so old records and exports render; they are display-only.

### Deferment & Ejection Internals

- **Deferment signal**: `_miwWeatherNeg`/`_micWeatherNeg` reads `_pfSampleWeather`/`_afSampleWeather(side)` on the favored side and defers while its dollar `value` is below zero, with no deadband, trim, or cooldown. It needs Sample Scoring and returns nothing until the scorecard has a headline.
- **Deferment effect**: the scan returns before every open path, with guards inside `_miwTrySubstitute`/`_micTrySubstitute` and `_miwOpen`/`_micOpen`. Historical scoring still runs. One `⛔ Deferment` log line per streak.
- **Ejection**: runs every scan ahead of slot logic (so it acts with no active slots) when the deferment state's `eject` is set, which needs two or more paths in `why`. `_miwEject`/`_micEject` closes every non-pending position of any strategy, each in its own try/catch, with one `⏏️ Ejection` log line naming the paths and close reason `ejection`. Each trade is scored against its opening criteria.

### Target Halving & Scorecard Deferment Internals

- **Targets**: `_miwTargets`/`_micTargets` resolves the factor from `_pfSampleWeather`/`_afSampleWeather(side)` on the favored side. It returns the configured values untouched (`active:false`) when Target Halving is off, neither Cascade nor Sacrifice is on, Sample Scoring is off, or there's no headline share (`wx.s`) or recorded share peak (`wx.sHi`). The factor is `clamp(wx.s / wx.sHi, 0, 1)`, zero when the peak is at or below zero. `_miwEffCascadePct`/`_micEffCascadePct` and `_miwEffSacrificePct`/`_micEffSacrificePct` return the resolved % floored at Min Entry TP and 1%; `_miwTargetsText`/`_micTargetsText` feed the Exit-tab readout.
- **Per-position overrides**: `_miwOpen`/`_micOpen` pass `_tpPct` and `_slPct` on the candidate. PseudoWinter/PseudoChaser use `_tpPct` for the entry TP, and `_slPct` for the binary-mode SL at open. It is also stored as `pos._slPctOverride`, which the DCA-mode SL arm, the SL drift check and the position card honor. Both candidate fields are excluded from the copy of candidate fields onto the position.
- **Deferment layering**: `_miwDefermentState`/`_micDefermentState` wraps `…DefermentStateBase`. The wrapper evaluates the negative-headline test (on with Deferment), Both Poles Red and the base on their own and merges them, with `why` listing those that hold and `eject` set when there are two or more. The base holds only the Target Halving floor test. `_miwWeatherNeg`/`_micWeatherNeg` and `_miwBothPolesRed`/`_micBothPolesRed` are the two clause tests; the latter reads the favored side of `pfLukewarmScoreboard`/`afLukewarmScoreboard`.
- **Headline source**: `_pfSampleBuild`/`_afSampleBuild` accumulates the raw edge per bucket into `pfSampleBucketMeans`/`afSampleBucketMeans` (`aE`/`aL`, counts `nAE`/`nAL`) and the signed favorable share `(P−Q)/(P+Q)` of those raw moves (`sE`/`sL`). `_pfSampleWeather`/`_afSampleWeather` returns the dollar `value`, the share (`s`, and `share` as 0–1) and the peak/bottom of each (`hi`/`lo`, `sHi`/`sLo`). `_pfSampleTrackWx`/`_afSampleTrackWx` keeps those peaks in the sample store as `wx`, and the leader shares them with followers. With Liquidation Surveillance on, `aE`/`aL`/`sE`/`sL` are the 50/50 mix of the price and liquidation figures, with the liquidation side joining once its bucket holds Min Samples; `nlE`/`nlL` report its count, `nE`/`nL` and `nAE`/`nAL` include it, and the weather's `nl` carries it for the tooltip. The bucket `extreme`/`lukewarm` means that pick the favored side are mixed the same way. `aE0`/`aL0`/`sE0`/`sL0` and `wxDrag` are still published, with `wxDrag` fixed at 1 (the removed Silence Penalty used to set it), so the Target Halving factor `s / sHi` and the negative-headline Deferment test read the mixed share and value directly.

### Extremity Scorer Internals

- **Cutoffs**: come from the sample pool (`pfDialSamplePool`/`afDialSamplePool`), fed by `_pfDialSample`/`_afDialSample` on every criterion annotation, not only trades, and persisted across reloads. A pole with at least **Min Samples** readings cuts off at its **Extreme Split** percentile; a reading at or above it is extreme, anything below it and everything on an unproven pole is lukewarm. Bare sign-only tags from Blind-Entry/Liquid-Diver (`+fund`/`-fund`/`+ocs`/`-ocs`) carry no magnitude and always classify extreme.
- **Two tallies**: the dial tally counts extreme occurrences only and is the flat `micCollapsedSlotRanks`/`micCollapsedCritStats` lookup that Co-Qualifying Penalty and entry ordering read. The Lukewarm Scoring tally counts every occurrence, bucketed by class then by pole (`fund+`/`fund-`, not merged by family, since a family's poles are opposite signals).
- **Favored side**: `_pfLukewarmFavoredSide`/`_afLukewarmFavoredSide`, re-decided each time the scorer rebuilds (once per scan cycle).
- **Veto**: `_pfExtremityVeto`/`_afExtremityVeto` counts the share of a candidate's dial-eligible criteria on the non-favored side and vetoes at **Lukewarm Veto**%. An unproven dial counts against the candidate. It checks every entry.
- **Pole Blocking**: `_miwPoleBlocked`/`_micPoleBlocked`, called from `_miwIsEntryBlocked`/`_micIsEntryBlocked` after the Lukewarm Veto, so it covers both the entry-pool filter and the post-top-up re-check. Reads the favored side of `pfLukewarmScoreboard`/`afLukewarmScoreboard`; inert without Sample Scoring.
- **Position Rolling Average**: when on, `_pfPositionCriteriaSample`/`_afPositionCriteriaSample` re-reads each open position's locked criteria families every scan and keeps a rolling 24h average per family, using a fresh single-ticker fetch and the cached 1h candle for `lta`/`lpa`. These fetches are exempt from Leader/Follower's no-own-fetch rule, like Force-Evaluate's. `_pfPositionAvgCriteria`/`_afPositionAvgCriteria` rebuilds the tag from the average, falling back to the frozen entry tag (`_miwCriteria`/`_micCriteria`, or the Blind-Entry/Liquid-Diver equivalents) for any family under **Min Samples** readings. Close-time scoring, Extremity Re-Evaluation and Substitution's live score all read that average. When off, nothing is fetched and only frozen tags are used; the cutoff sample pool is unaffected either way.
- **Sample Scoring**: when on, `_pfExtremityBuild`/`_afExtremityBuild` returns `_pfSampleBuild`/`_afSampleBuild` instead of walking closed records. It publishes the same outputs (cutoffs, `micCollapsedSlotRanks`/`miwCollapsedSlotRanks`, the two-bucket scoreboard) from `__ew_*_sampleobs_v1`, plus the per-bucket mean edge (`pfSampleBucketMeans`/`afSampleBucketMeans`) for the favored side. `_pfSampleIngest`/`_afSampleIngest` runs with each new sample cycle and stores one observation per ticker: its criteria tags at sample time, `y` (the last completed hour's price change minus the rolling LPA average from `_pfLpaWindowAvg`/`_afLpaWindowAvg`) and `r` (the raw change). The build keeps only each ticker's latest observation per clock hour and skips `lpa` tags on price observations. The leader publishes `sampleScore` on the shared registry and a follower adopts it each scan (`_pfSampleAdopt`/`_afSampleAdopt`).
- **Period Scorer**: `_pfPeriodIngest`/`_afPeriodIngest` runs after each sample cycle's ingest on the leader; a follower adopts the leader's store with `_pfPeriodAdopt`/`_afPeriodAdopt`. It reduces the cycle to its five averages (a type needs 3+ readings, and a batch without a price average is dropped), grades the live forecast (`_pfPeriodGrade`/`_afPeriodGrade`), issues a new forecast once the previous slice has fully closed (`_pfPeriodForecastIfDue`/`_afPeriodForecastIfDue` → `_pfPeriodForecast`/`_afPeriodForecast`, which needs four slices of records) and saves. A forecast is dropped as stale if a batch arrives more than 3× the scan interval per step after it was made. The forecast works in z-units: for each data type and step k it picks the slice-average series with the largest |r| over the realized pairs (at least 8, no look-ahead) and applies its least-squares line, shrunk by n/(n+10). `_pfPeriodScore`/`_afPeriodScore` returns null unless `_pfPeriodStatus`/`_afPeriodStatus` is `live`, and its extreme cutoff comes from the projected estimates (the graded ones plus the current forecast), because projections are shrunk toward the average and a cutoff taken from realized values would almost never be reached, leaving everything lukewarm. `_pfSampleBuild`/`_afSampleBuild` folds it in with `_pw`: a pole's score becomes `(1 − w) × score + w × period mean` when it already has a base score (otherwise `w × period mean`), and the bucket means, raw means and shares are mixed the same way only when the base figure exists. With weight 0, the toggle off, a closed accuracy gate, or a following bot without a store, the plain Sample Scoring output is untouched. LPA's batch average only changes with the clock hour (every batch in an hour reads the same completed candle), so its accuracy is flattered by projected batches that fall in an hour already known; read it alongside the other types.
- **Graylist**: there are two lists. The quiet graylist `lgray` (symbol → time it was found quiet) sits in the sample store and is written and read only by `_pfLiqPick`/`_afLiqPick`; a quiet ticker is simply not picked for the batch until the pool runs short, and it stays a normal entry candidate. The Instability graylist blocks entries and isn't stored: `_pfInstabStats`/`_afInstabStats` (memoized per history state and a `_pfLiqVer`/`_afLiqVer` counter, since `lu`/`ld` are written onto cycles already in history) sums `lu`/`ld` per symbol over the retained cycles, needs `pfInstabMinWatches`/`afInstabMinWatches` (2, no UI) watches with liquidations, scores `1 − |U − D|/(U + D)`, and flags symbols at or above `avg × (1 + Instability %/100)`. `_pfGrayHas`/`_afGrayHas` (checked in `_miwScanFetch`/`_micScanFetch`, counted as `excluded.gray`) returns true for that set, plus the old time-based `st.gray` for a leader (`pfDistMins`/`afDistMins`; nothing writes it any more). The Instability check works while following, and neither list does anything when Sample Scoring or Liquidation Surveillance is off. `_pfLiqPillClass`/`_afLiqPillClass` classifies a watch for the pills from `lu`/`ld`, falling back to the sign of `lq` on older cycles.
- **Thin poles**: a pole under **Min Samples** scores 0 and counts as lukewarm; at Min Samples its score becomes the plain mean of those readings with no shrinkage, so a rare pole (e.g. `fund-`) jumps from neutral to full weight on a handful of readings. Entry ordering discounts thin poles separately (see **Sparsity**).
- **Liquidation Surveillance**: the feed is `allLiquidation.<symbol>` on the public linear WebSocket, held at module level in `LIQ`: the socket, its subscriptions, the per-symbol tally `{up, dn, n}` (up = liquidated-short turnover, down = liquidated-long turnover, `S:'Buy'` meaning a long was liquidated), the watched set and the closed watch awaiting scoring.
  - **Feed**: subscriptions are diffed and sent 10 per request, with a 20 s ping and 5 s reconnect (`_pfLiqWsSync`/`_afLiqWsSync`, `_pfLiqWsApply`/`_afLiqWsApply`), and only while `_pfLiqOn()`/`_afLiqOn()` holds (toggle on, Sample Scoring on, not following).
  - **Picking**: `_miwScanFetch`/`_micScanFetch` calls `_pfLiqPick(pool, cap)`/`_afLiqPick` with the shuffled pool. It closes the watch that just ran (snapshots and resets the tally; a watched ticker with events that is still in the pool is kept, most turnover first, and every watched ticker without events goes into `lgray`). It then fills the batch with the kept tickers, fresh non-graylisted ones and, only if still short, the oldest-graylisted (removed from `lgray` as they return), and subscribes the new set. It returns null when off or following, and the random batch stands.
  - **Ingest**: after that scan's batch lands, `_pfSampleIngest`/`_afSampleIngest` calls `_pfLiqIngest`/`_afLiqIngest`. It writes one `k:'l'` observation per ticker with events: criteria from the fresh reading (`_pfSampleTags` with LPA included), `y = (up − dn)/(up + dn)`, `r = y × S` and `w = up + dn`, where `S` (`_pfLiqScale`/`_afLiqScale`) is the median of |latest 1h change − window average| over each ticker's latest reading (floor 0.05pp). A ticker with events that wasn't re-fetched (more liquidated tickers than the batch holds) gets none.
  - **Cycle stamps and sharing**: it also stamps `lq` (the lean in pp, 0 for watched-but-quiet) and, for tickers with events, `lu`/`ld` (liquidated-short / liquidated-long turnover in $) on the cycle the watch began on. The Liq chart view reads `lq`, and the pills and Instability Graylist read `lu`/`ld`. The leader also publishes the lean on the shared registry as `liqLean` (`{cts, lq, ls}`, `ls` being the `lu`/`ld` split per symbol), keyed by the ts the cycle was published under (stamped on the cycle as `pub` after the `ocResults` write). A follower's `_pfLiqAdopt`/`_afLiqAdopt`, run at the end of `_ocSeedFromShared`, files it on the matching cycle of its own history, trying again next scan if that cycle isn't there yet.
  - **Build**: `_pfSampleBuild`/`_afSampleBuild` ignores `k:'l'` observations while the toggle is off. Otherwise each is parsed like a price observation (`edge = dir × r`, with `dir` −1 on Winter and +1 on Chaser), weighted `min(3, w / median w)`, added to the same pole pool and cutoffs and bucketed by them. The pole scores, favored-side means and headline figures are the 50/50 mixes described in **Headline source**.
  - **Caveat**: the LPA window average, V/A and IO/A baselines and the Silence readout read each ticker's latest reading, so a batch weighted toward tickers that keep liquidating tilts those baselines toward active names.
  - **Persistence**: the watch persists to `__af_liq_pending`/`__pf_liq_pending` (4 s throttle while events arrive, plus each pick, ingest and page hide). The first pick after a reload restores it (dropping anything older than 12 h), reconnects the feed, and the next ingest scores it like any other. Price and liquidation observations are trimmed to the byte cap separately (`_pfObsTrim`/`_afObsTrim`).
- **Silence Amplifier**:
  - **Limit and factor**: `_pfSilAmpLimit`/`_afSilAmpLimit` is the mean distance of the window's latest LPA readings from their mean, times `1 + Noisy %`. `_pfSilAmpFactor`/`_afSilAmpFactor(q, limit)` returns `1 + Boost %` when the noise `q` exceeds it, and 1 otherwise.
  - **Build**: `_pfSampleBuild`/`_afSampleBuild` multiplies each price observation's edge and raw move by the factor of `|y|` (already its distance from the average), and each liquidation observation's edge by the factor of its stored `q` (an observation without `q` isn't boosted). Tier tags, cutoffs and sample counts are untouched; only edges and raw moves scale, so the poles, the favored side and the headline all move.
  - **Re-sampling**: `_pfResamplePick`/`_afResamplePick(pool, cap)` is called by `_miwScanFetch`/`_micScanFetch` right after `_pfLiqPick`/`_afLiqPick` returns nothing (toggle off or following). It takes each ticker's latest LPA reading and cycle time from the retained cycle history, drops counts for tickers no longer anywhere in the window, picks noisy candidates (not at max, not read this clock hour) noisiest first up to the reserved share, bumps their count, and returns them ahead of the shuffled pool with capped tickers filtered out. Counts persist in `__ew_*_rs_v1`. It returns `null` when off or following, so the random batch stands.
- **Sparsity**: `_pfPoleData`/`_afPoleData` returns the sample count behind the bucket a tier tag lands in (Extreme or Lukewarm, by the pole's cutoff) and the median count across that bucket type's poles, read from the scoreboard (so liquidation samples count). It returns `null` for a family with no scoreboard entry at all (LPA under Sample Scoring), so `_pfSparseOne`/`_afSparseOne` skips it instead of treating it as an empty pole. `_pfSparse`/`_afSparse` turns a candidate's tags into a factor (the thinnest pole's `n / (n + Min Samples)`) and a block flag (thinnest pole under the floor % of the median). MIW/MIC apply the per-pole factor in `_miwScaledRank`/`_micScaledRank`, multiply the Co-Qual-off richness sort by the candidate's factor, and check the block flag in `_miwIsEntryBlocked`/`_micIsEntryBlocked`, which covers the entry-pool filter and the post-top-up re-check. It's inert until a scoreboard exists.
- **Win/loss counts can appear high**: a criterion shared across many slots accumulates records from all of them, and the Sponge Quota caps per criterion, not per slot.

### Cross-Tab Data Pool

Both bots share market data via `localStorage.__ew_shared_v1` and `BroadcastChannel('ew_shared')`. Writes are last-write-wins per data type. Either bot operates normally solo — the registry is simply absent and all ladder checks fall through to normal fetches.

Each bot publishes its own open-symbol list to this registry on every position open/close, and once more per heartbeat as a safety net for close paths that bypass `pseudoClosePosition` (e.g. the gap-fill audit). A following bot (`lfFollowPartner` on, partner heartbeat fresh) checks the leader's list before opening and skips any ticker the leader already holds; the leader never checks its own publish. Since the check only runs while `_lfIsFollowing()` is true, it switches itself off the instant the leader's heartbeat goes stale, with no separate expiry logic on the position data.

Not every `BroadcastChannel('ew_shared')` message carries a `localStorage.__ew_shared_v1` write behind it, though most do (`_sharedWrite`/`_sharedMerge` post a change notification after writing). `registerSharedMessageHook` is the general subscription point either kind of push is dispatched through on the receiving end.

### Scan Scheduler Internals

- **Stages**: `runScan` calls `_scanPipeline(ctx)`, which runs the host's `tickers` stage, then each plugin stage in load order (`pf-post`/`af-post`, then `miw-`/`mic-` `prep`, `fetch`, `pool`, `entry`). Stages share `ctx`; a plugin appends `{ id, group, run }` to `_scanStageDefs` in `transform`, and a stage returning `false` skips the rest of its group. On a host without `_scanStageDefs` the plugin falls back to wrapping `runScan`.
- **Checkpoints**: loops call `if (this._scanDue()) await this._scanCp()`, which yields once `schedSliceMs` has elapsed (40 ms while the tab is hidden). The yield is a `MessageChannel` task rather than `setTimeout`, because a hidden tab clamps timers to 1 s or more.
- **Idle lane**: `_schIdle(key, fn)` queues one coalesced job per key (extremity rebuild, re-eval, sample-store saves), flushed when the pipeline ends; `_schIdleCancel(key)` drops it, which MIW/MIC's own rebuild uses to supersede Permafrost/Ashfall's.
- **Timing**: each scan logs one `[SCH]` line with total ms, yields, long-task count and per-stage ms. `ui.scanning` stays on through the plugin stages, so a batch that outlasts the scan interval makes the next scan skip. The extremity rebuild itself is still one synchronous call.
- Every background or bulk fetch (bulk tickers, market watch, and any loaded plugin's kline and sample batches) runs through a single per-bot scheduling queue (**Scan Scheduling** in Main Config) instead of firing all at once. This keeps the browser responsive with one bot open and workable with two. Execution-critical single-symbol calls (opening, closing and watching a position) bypass the queue so order execution is never delayed behind background scanning. The scan itself is a pipeline of named stages that hands control back to the browser after each time slice (**Slice Budget**), so position watching, clicks and timers run mid-scan instead of waiting for it to finish.
- **Running both bots**: When both are open simultaneously they automatically share bulk ticker fetches, kline caches, and sample batches to halve API load. Either bot works normally on its own when the other tab isn't open.

### Plugin Transform Pipeline

```
pw()  →  plugin[0].transform(def)  →  plugin[1].transform(def)  →  ...  →  Alpine
```

Each plugin's `transform(def)` receives and returns the component definition, so load order matters for method wrapping. Strategy plugins must declare `after: ['everwinter']` / `after: ['sunchaser']` so the live-trading plugin's wraps are innermost, which means live-trading plugins (EverWinter, SunChaser) must load before strategy plugins (MultiIndicator, Permafrost/Ashfall). ### Bybit API Endpoints Used

**Public**: `GET /v5/market/tickers` (bulk for the symbol universe, per symbol for criteria data), `GET /v5/market/recent-trade`, `GET /v5/market/kline`, `GET /v5/market/instruments-info`. **WebSocket**: `wss://stream.bybit.com/v5/public/linear` (position price stream). **Signed (live plugins only)**: `GET /v5/account/wallet-balance`, `GET /v5/position/list`, `POST /v5/order/create`, `POST /v5/position/trading-stop`, `POST /v5/order/cancel`. Signing: HMAC-SHA-256 via `crypto.subtle.sign`; 250ms minimum gap between signed requests.
