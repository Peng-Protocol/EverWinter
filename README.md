# ❄️ EVERWINTER

**EverWinter** is a browser-based trading suite for Bybit USDT Perpetuals executing the **Winter-Chaser** strategy. See the [Strategy Guide](StrategyBook.md) for trading logic and rationale.

## Setup

Open any `.html` file directly in a browser. No build step, no server, no installation. Alpine.js and Bootstrap 5 are loaded from CDN — an internet connection is required on first load (cached after that).

To trade proactively, run `PseudoChaser` (longs only) with `MultiIndicator` and `Ashfall` loaded, or `PseudoWinter` (shorts only) with `MultiIndicator` and `Permafrost` loaded. To trade reactively, run `PsychoChaser` (longs only) or `PsychoWinter` (shorts only) on their own.

The Strategy Book explains how the Reactive and Proactive approaches differ, and the Psycho Handbook covers the Reactive bots' configs in depth.

## Menus

The UI has four views: **Market** (positions, scan controls, watchlist) plus three configuration/telemetry panels — **Config**, **Stats**, and **Trades**.

**Mobile** (≤768px): a bottom tab bar (⚙ Config · 📊 Market · 📈 Stats · 📌 Trades) switches between the four views full-screen, one at a time. Unchanged from earlier builds.

**Desktop**: Market, Config, Stats and Trades all sit side by side in normal document flow at the same level — no overlay, no dimming, no shadow. Config/Stats/Trades open via matching icon buttons (⚙ 📈 📌) in the topbar — no dedicated Market button, since it's never hidden. Config opens by default on launch; click its icon again (or any open panel's icon) to dismiss it.

Market is always twice as wide as one side panel. With both side panels open the split is Market 2/4, left panel 1/4, right panel 1/4; with one panel open it's roughly 2:1; with none, Market fills the row. Panels take slots in the order they're opened, not by which menu they are:
- First panel opened → left slot. Second → right slot.
- Once both slots are full, opening a third (currently-closed) panel replaces the **left** slot's occupant.
- Opening a fourth replaces the **right** slot's occupant — and it keeps alternating left/right on every subsequent replacement from there.

Two panels can be open at once; a third click always bumps whichever slot is due next rather than stacking a third panel.

## Plugins

## EverWinter / SunChaser (Live Trading Plugins)

EverWinter turns PseudoWinter into a live short-only Bybit bot; SunChaser does the same for PseudoChaser as long-only. Both sign requests with the stored `__ew_creds`/`__sc_creds` API key and place real orders — the topbar reads **Very Real Orders** once loaded, in place of the base simulation's **No Real Orders**.

### Order Handling (Open / Close tabs)

The plugin's accordion has three tabs: **API** (credentials), **Open** and **Close**. 

**Limit** here means a limit priced through the last price by the **Limit offset** (default 0.1%: entries sell below / buy above, closes buy above / sell below), so it normally fills like a taker. A negative offset makes it passive. **Market** sends a market order (IOC for entries, reduce-only IOC for closes). A **try** is one limit order: it waits for a fill, then is cancelled and repriced off a fresh last price.

**Open tab**

| Setting | What it does |
|---|---|
| **Order type** (`ewOpenType`/`scOpenType`, default Limit) | Limit or Market entry. |
| **Limit offset** (`…OpenOffsetPct`, default 0.1) | Distance through last price, in %. |
| **Limit tries** (`…OpenTries`, default **1**, 1–20) | Limit attempts before the fallback (or giving up). |
| **Fall back to market** (`…OpenFallback`, default **on**) | After the limit tries go unfilled, send one market order. Off: give up and put the symbol on cooldown. |
| **Fill timeout per try** (`…FillTimeoutMs`, default 10 s) | How long each limit try waits for a fill before it's cancelled. |
| **Cooldown after failed open** (`…FillCooldownMs`, default 15 min) | How long a symbol is skipped after an entry that placed an order but never filled. A rejected order doesn't trigger it. |

**Close tab** (applies to every bot-initiated close: manual, runtime, cascade/sacrifice, bail sweeps and the post-bail re-check. Exchange-native TP/SL closes are filled by the exchange and aren't affected)

| Setting | What it does |
|---|---|
| **Order type** (`…CloseType`, default Limit) | Limit or Market (reduce-only) close. |
| **Limit offset** (`…CloseOffsetPct`, default 0.1) | Distance through last price, in %. |
| **Limit tries** (`…CloseTries`, default **10**, 1–100) | Reduce-only limit attempts before the fallback. |
| **Fall back to market** (`…CloseFallback`, default **on**) | After the limit tries go unfilled, close with a reduce-only market order, repeated until flat. Off: keeps repricing the limit until the position is flat; a close never gives up. |
| **Reprice interval** (`…CloseRetryMs`, default 10 s) | Time between close tries. After the fallback, market closes repeat at most every 4 s. |

With the defaults, an entry that doesn't fill on its first limit goes to market, and a close that hasn't filled after ten limit tries (about 100 s) goes to market.

## Main Config

Changes take effect immediately and are persisted to localStorage automatically.

| Setting | What it does |
|---|---|
| **Scan Interval** (`scanMins`) | How often (minutes) the bot runs a full market scan. Controls both entry frequency and the scan bar in the UI. |
| **Max Positions** (`maxPos`) | Maximum simultaneously open positions. No new entries open once this is reached. |
| **Leverage** (`leverage`) | Position leverage. Affects order size, TP/SL prices, and EDa thresholds. |
| **Min Notional** (`minNotional`) | Base margin per position in USDT. Actual order size = minNotional × leverage. |
| **Entry TP** (`entryTpRoi`, default 50%) | Take-profit ROI % target. When EDa is active this is the buffered target — the debt-free close happens at a lower percentage. In DCA Mode this is also the base the per-stage TP ladder scales down from (entry TP ÷ (stage+1), min 3%). |
| **Binary Mode** (`binaryModeEnabled`) | On: every position gets a take-profit and a stop-loss at entry and no DCA adds (`binaryTpPct`/`binarySlPct`, both default 50%). Off: multi-stage DCA. Add orders trigger below entry (PseudoChaser) or above it (PseudoWinter), each with a lower TP ROI target, and the stop-loss (`dcaSlPct`, default 16%) only arms once every first-wind DCA stage has filled. The DCA config controls need the `dca-long`/`dca-short` plugin (`plugins/modes/`); the binary and DCA logic itself is in the base bot either way. |
| **DCA Stages** (`dcaStages`, default 1) | Number of DCA add orders (1–6 in the plugin slider). Each stage has its own trigger slider (`dcaAddPct1`…`dcaAddPct6`, defaults 3 / 6 / 12 / 18 / 24 / 30), set as % below entry for PseudoChaser or above entry for PseudoWinter, and only the sliders for selected stages appear. Triggers always increase by stage: lowering one stops at the previous stage's trigger, and raising one pushes the later stages up. Configs saved before per-stage triggers (a fixed 1.5%, then +3% per stage for non-3 stage counts) are migrated on load/import so they keep the same trigger prices. |
| **DCA Add Notional** (`addNotional`) | Margin (USDT) added per DCA stage — separate from **Min Notional**, which only sizes the initial entry. |
| **Drawdown Throttle** (`drawdownThrottleEnabled`) | Halts new entries for `drawdownHaltHours` (default 12h, free-entry field with no upper bound) when the rolling 6h realized PnL falls below a loss threshold. The Halt tab shows the live 6h rolling PnL. Its **Clear 6hr Record** button (with confirmation) zeroes that window manually, whether or not a halt is active. |
| **Drawdown Factor** (`drawdownThrottleFactor`) | Loss threshold as a multiple of entry margin. At 0.5× with $1 margin, $0.50 of rolling losses triggers the halt. |
| **Bail on Trigger** (`drawdownBailEnabled`, default on) | When on, triggering the Drawdown Throttle halt also immediately closes every open position at market (`bailAll()`) — the same sweep the Danger Zone's manual **Bail All Positions** button runs, and what the **BAIL** trade-card badge marks. |
| **Gains Lock** (`gainsLockEnabled`) | Halts new entries for 12 hours once rolling 6h profit hits a target. Banks a winning streak before it reverses. Same 6h rolling PnL readout and **Clear 6hr Record** button as Drawdown Throttle, shown in its own section of the Halt tab. |
| **Gains Factor** (`gainsLockFactor`) | Profit target as a multiple of entry margin. Same scale as Drawdown Factor. |
| **Manual Halt** | Button (Halt tab) that blocks all new position entry indefinitely until manually lifted. Independent of Drawdown Throttle and Gains Lock — overrides both and doesn't stack with either. |
| **EDa / Laggard Check** (`laggardCheckEnabled`) | Enables the Effective Debt Adjusted system. Realized losses are passed forward to surviving positions, which take higher TP targets to recover the debt. **Requires the EDa-Winter / EDa-Chaser plugin** (`plugins/modes/`). |
| **TP Buffer** (`laggardProfitOffset`) | Extra TP headroom reserved above the functional target (%). The debt-free close happens at `tpPct ÷ (1 + buffer/100)` — at 50% buffer with an 18% TP slider, trades close at 12% without debt. Requires the EDa plugin. |
| **Ticker Cooldown** (`bulkTickerCooldownHours`) | How long the bot reuses a cached bulk ticker fetch before hitting the API again (default 12h). The bulk list only says which symbols exist — criteria data never reads it — and the same window sets how long MIW/MIC's re-entry block and the Ticker Graylist hold a closed symbol. |
| **Whiplash Audit** (`whiplashEnabled`) | When on, the position watcher fetches 1-minute klines near TP to confirm whether price spiked through TP between watcher cycles. |
| **Whiplash Proximity** (`whiplashProximityPct`) | How close (%) to TP price triggers the kline audit. |
| **Runtime Limit** (`runtimeHours`) | Maximum position age. Forces a close at the deadline if TP hasn't been hit. |
| **Symbol Banlist** (`banlistEnabled`) | When on, symbols on the ban list are excluded from all scans. Entries expire after 7 days. |
| **Position Price Feed** (`restPollEnabled`) | When on, replaces the WebSocket price stream for open positions with periodic REST API calls. Use if the WS feed returns stale or incorrect prices. Exactly one source runs at a time: turning it on closes the WebSocket stream, and turning it off stops the REST calls. Pseudo bots default to on. Psycho bots default to off (WebSocket only), and a saved Psycho config is switched off once on first load of PsychoChaser v1.9.1 / PsychoWinter v1.12.1; turn it back on if WS prices look wrong. |
| **Price Poll Interval** (`restPollBaseSec`) | Base polling interval in seconds for REST mode. The interval doubles automatically when price moves less than 0.1% between ticks and resets to base on any meaningful move. |
| **Dispatch Every** (`schedIntervalMs`) | Minimum gap (ms, default 150) between successive background fetches dispatched from the scheduling queue. Lower = faster background data turnover, at the cost of more simultaneous requests. |
| **Max Concurrent** (`schedMaxConcurrent`) | Hard cap (default 4) on background fetches in flight at once, regardless of how many subsystems have work queued. |
| **Slice Budget** (`schedSliceMs`) | How long (ms, default 8, 2–30) a scan stage runs before handing the browser back; a hidden tab uses 40 ms. Lower = smoother page, slightly slower scans. |
| **Follow Partner Bot** (`lfFollowPartner`) | When on, this bot stops fetching bulk tickers itself and uses the partner's shared cache. If the partner hasn't shared a bulk ticker list (or it has been evicted from the shared registry), it reuses its own cached list while that is still within **Ticker Cooldown**, and otherwise fetches one bulk list itself rather than sitting idle with no tickers (for example right after a page reload). Everything else it fetches stays on the leader. The partner needs no toggle: it acts as leader while its heartbeat (written once per completed scan cycle) is fresh, meaning newer than 2× **Scan Interval**. If the partner goes stale, this bot resumes scanning on its own, and it steps back down as soon as the partner returns. It also won't open a position on any ticker the leader already holds, checked at entry before any instrument or price lookups. Permafrost/Ashfall ignore this setting and always sample independently. |
| **Config Lock** (`cfgLocked`) | Locks all config controls to prevent accidental changes; it engages automatically while the bot is running. On EverWinter/SunChaser it also locks the Open and Close tab controls (the tabs themselves stay navigable). |

## Stats Menu

The stats panel shows session-level metrics since the page was last loaded or state was cleared.

| Stat | Meaning |
|---|---|
| **Session PnL** | Cumulative realized PnL from all closed trades this session. |
| **Win / Loss** | Count of profitable vs. losing closed trades. |
| **Win Skew** | Share of total PnL magnitude (all closed trades, cumulative) that came from wins — sum of winning PnL ÷ (sum of winning PnL + sum of losing PnL). Weighted by trade size, not just a count of wins vs. losses. |
| **Avg PnL** | Mean realized PnL per closed trade. |
| **Open uPnL** | Unrealized PnL across all currently open positions. |
| **Positions** | Count of open positions. |
| **Last Scan** | Timestamp of the most recent scan cycle. |
| **Laggard** | The oldest open position — the EDa debt holder. Shows its current debt load when EDa is active. |
| **Persistence** | "Active" (live in-memory position count) vs. "Stored" (confirmed saved to localStorage). These should always match. |

**Persistence mismatch**: shown in red with a warning banner. It means a save failed or was overwritten, and usually clears on its own within a few seconds as the bot retries automatically. If it doesn't:
- Check the activity log for `[PST]`/`[PERSIST]` entries.
- Close any duplicate tabs of the same bot — a second tab can overwrite the first tab's saves with its own stale position count.

**Storage usage** (dropdown below Persistence, PseudoWinter/PseudoChaser only): breaks this bot's localStorage footprint down to one row per data type, including genuinely shared cross-bot keys but never the partner's private state. Oversized rows show in red with a **✕** to clear that bucket (with confirmation), and **Export** downloads the breakdown as a text file.

**Power usage** (dropdown below Storage usage): a rolling average and peak of how many milliseconds the app spends reacting each second. A rising figure usually means a plugin panel left open somewhere is doing more work than it needs to — closing analytics panels you're not actively watching brings it back down.

**Ticker Graylist**: when MultiIndicator is enabled, the Stats menu shows a Ticker Graylist section listing symbols currently blocked from re-entry. It's empty when nothing is blocked. Each listed symbol clears itself automatically once the bulk ticker cooldown window elapses — no manual action needed.

### Actions Dropdown

- **Export** — Downloads current bot state (config, positions, closed trades, ban list, EDa state) as a `.json` file. Plugins with their own data (Permafrost/Ashfall scorer data) have their own Export in the Danger Zone of their accordions (see **Export & Import** under Permafrost / Ashfall Plugin) — the Stats menu Export covers the base bot state only.
- **Import** — Restores state from a previously exported `.json` file. Config fields merge field by field, while positions are replaced wholesale. A 5s debounce prevents accidental double-imports. Config keys that no longer belong to a loaded feature (the bot or an installed plugin) are dropped on import and on every save, so retired settings don't linger.
- **Clear Closed Trades** — Wipes the closed trades list, resets session stats, and clears the 6hr drawdown/gains-lock rolling PnL windows. Open positions are unaffected.
- **Clear All** — Full reset. All positions, trades, stats, and config are wiped (config reverts to defaults).

### Activity Log

Timestamped entries for every significant bot event. Color coding:

- **White** — informational (scan results, entries, closes)
- **Yellow** — warnings (halts engaged, API retries)
- **Red** — errors (API failures, plugin conflicts)

Common prefixes: `[MHL]` manual halt · `[DWN]` drawdown throttle · `[GLK]` gains lock · `[PST]` (PseudoWinter) / `[PERSIST]` (PseudoChaser) save failures or recovered positions · `[PFR]`/`[ASH]` climate plugin events · `[MIW]`/`[MIC]` multi-indicator events.

The log keeps the latest 300 entries in memory and in localStorage, dropping the oldest first. Each entry has a local `HH:MM:SS` string (`t`), which is what the UI shows, and an epoch-millisecond timestamp (`ts`). `ts` lets you match a log export to position and config exports, which are timestamped in UTC epoch; `t` alone can't be tied to a date or time zone.

## Trades Menu

The trades panel shows a card for each closed trade, newest first, with a close-reason badge: **TP**, **SL**, **FORCE** (runtime limit), **BAIL** (drawdown throttle bail, which closes every open position immediately on both bots), **Sub** (closed to free a slot for a higher-ranked candidate via MIW/MIC Substitution) or **Eject** (closed by MIW/MIC Ejection when two or more Deferment paths are active at once). Reasons added by other plugins show their own label, or the raw reason name if none is registered. On EverWinter/SunChaser, a bail sweep is followed by a direct exchange re-check. In the simulation bots, each card also shows estimated fees (`FEE_MAKER_PCT` 0.02% on entry and DCA fills, `FEE_TAKER_PCT` 0.055% on the close, the Bybit base-tier rates), and Net PnL, win/loss and the drawdown and gains windows are net of them; live positions are skipped.

**Roll-up card**: when the closed trades list exceeds 50 entries, the oldest are compacted into a single roll-up card showing their net PnL, trade count, and the date range they cover. The roll-up is not a trade — it is a historical summary. In the PnL chart, the roll-up's net value acts as a baseline offset applied to every plotted point.

**PnL chart**: click the **PNL CHART** bar below the header to expand a cumulative PnL line chart. The X-axis spans from the first to the last individual closed trade at fixed spacing. The chart is green when the net result is positive, red when negative. The chart only appears once at least 2 individual trades are closed.

**CLEAR button**: removes all closed trades, resets session stats, and clears the 6hr drawdown/gains-lock rolling PnL windows. Clicking CLEAR reveals an inline confirmation ("Sure? Yes / No") before anything is deleted. Yes confirms; No cancels with no change.

## MultiIndicator Plugin (MIW / MIC)

The Multi-Indicator plugin filters entries with combinations of criteria called **slots**. A slot is an AND-gate: every criterion in it must be true for a ticker to qualify, and a ticker only needs to match one slot to be eligible for entry. No criterion is mandatory; a slot (Auto or manual) can use any combination of `fund`, `va`, `iol`, `ios`, `lta` and `lpa`. Entry is scan-driven only: one pass per fresh sample batch.

### Criteria

See StrategyBook's **Market Reading** section for what each criterion means and when to use it. This section covers tiering, recording, and fetch mechanics only.

**Slot builder badge key**: the manual slot builder uses the same emoji set as position/trade badges.

| Badge | Criterion |
|---|---|
| 🤑/💸 | Funding tier (direction-aware, see [Trivia](#trivia). |
| 🔊 | V/A, volume versus the population sample-window average. |
| 🐂 | IO/L, the long share of the ticker's open interest versus the population sample-window average of that share. |
| 🐻 | IO/S, the same for the short share. |
| 🕐 | LTA, last completed hour's turnover versus the ticker's own average hour. |
| 💹 | LPA, last completed hour's price change versus every other ticker in the sample window. |

**IO/L and IO/S**: a ticker's long share of open interest is its open interest × the long share of accounts from Bybit's long/short ratio, and its short share is the remainder. The tier is `floor(100 × ln(share ÷ window average) ÷ step)`, so `iol+12` is 12 tiers more long open interest than the sampled population averages and `ios-3` is 3 tiers less short. They replaced IO/A (`ioa`, open interest alone) in 1.106.0. Each needs the ticker's long share, which the sample batch reads (one fresh read before entry when a candidate has none), and a window average, so it has no tier until the sample window holds readings. Saved manual slots that still use `ioa` never match; they are flagged once in the log and have to be replaced by IO/L or IO/S by hand.

**Recording**: every criterion is recorded as a signed tier on the position at entry.

### Config

| Setting | What it does |
|---|---|
| **Enabled** (`miwEnabled`/`micEnabled`) | Master on/off. When off, the plugin opens no entries and runs no exits. |
| **Picks** (`miwPicks`/`micPicks`) | Max new entries per scan cycle (1–10). |
| **Share Cap** (`miwShareCapEnabled`/`micShareCapEnabled`) | Limits plugin entries to a percentage of `maxPos`. Prevents MIW/MIC from filling all position slots. |
| **Share Cap %** (`miwShareCapPct`/`micShareCapPct`) | The cap percentage. At 50% with maxPos=6, MIW/MIC can hold at most 3 positions. |
| **Tier Step Sizes** (`miwFundStep`/`miwVaStep`/`miwIolStep`/`miwIosStep`/`miwLtaStep`/`miwLpaStep` and `mic` equivalents) | Read-only chips on the **Fetch** tab showing the tier step for each criterion. Defaults: `va` 1% deviation from the population average; `iol` and `ios` 1% (log) deviation of the long / short open-interest share from its window average; `lta` 10% deviation from the ticker's own hourly average; `lpa` 0.25 absolute points of 1h price change (shown as `pp`); `fund` 0.0025% of funding rate per tier, so 0.25% is tier 100. They can't be edited from the UI; change them via config import. Older installs saved the fund step as 0.25; it's migrated once, and saved `fund>N`/`fund<N` slot gates are rescaled ×100 so each keeps its threshold. |
| **Cascade** (`miwCascadeEnabled`/`micCascadeEnabled`) | Closes every open position, whichever strategy opened it, when their collective unrealized profit reaches a threshold, banking a group move before it reverses. The position watcher checks this every 5s while the bot runs, not just once per scan, so a threshold crossed and reversed between scans is still caught. The closes are sent concurrently, not one after another. |
| **Cascade %** (`miwCascadePct`/`micCascadePct`) | Collective uPnL trigger as a % of base margin (minNotional ÷ leverage). While **Relative Target** is on the slider is hidden and unused: Cascade fires at the resolved entry TP. |
| **Sacrifice** (`miwSacrificeEnabled`/`micSacrificeEnabled`) | Closes every open position, whichever strategy opened it, when their collective unrealized loss reaches a threshold, capping group drawdown. It uses the same continuous position-watcher check as Cascade, and closes concurrently the same way. |
| **Sacrifice %** (`miwSacrificePct`/`micSacrificePct`) | Collective uLoss trigger as a % of base margin (minNotional ÷ leverage). While **Relative Target** is on the slider is hidden and unused: Sacrifice fires at the resolved SL. |
| **Relative Target** (`miwRelativeTargetEnabled`/`micRelativeTargetEnabled`, default on; replaced Target Halving, and a saved Target Halving on/off choice carries over once) | Sub-toggle on the **Exit** tab, shown only while Cascade or Sacrifice is on. It sets each new position's entry TP and SL from what the market is actually paying: the LPA sample window's **average move in the bot's favor** × leverage is the entry TP, and the **average move against it** × leverage is the SL. On Chaser that is the average up move for TP and the average down move for SL; on Winter it is mirrored. Price move % × leverage is the ROI % the host's TP and SL use, so with a +2.5% average up move at 6× leverage Chaser's TP is 15%. **Cascade** is the entry TP and **Sacrifice** is the SL, so all four always agree. While it's on, the Cascade/Sacrifice sliders are hidden and unused, and a read-only line under the toggle shows the live averages, the resolved targets and the batch and ticker counts behind them. It also drives Deferment. It needs no Sample Scoring, only the LPA window: with fewer than 3 readings on either side of zero in the window, the configured values apply and Deferment's floor path is off. |
| **Window** (`miwRelBatches`/`micRelBatches`, default **6**, 1–25) | Shown only while Relative Target is on. How many of the latest sample batches the average moves are taken from; older batches are ignored so stale readings don't dilute them. Within those batches each ticker counts once, by its latest reading. A short window reacts faster, so targets and deferment swing more from batch to batch; 25 is the most batches the sample history keeps. |
| **Min Entry TP** (`miwMinEntryTp`/`micMinEntryTp`, default **6**) | Shown only while Relative Target is on. This is the ROI % below which a position can't cover its entry and exit fees. If the resolved entry TP (Cascade is the same number) falls under it, the market isn't paying enough to trade and new entries are deferred. At 6× leverage that means the window's average favorable 1h move has to be at least 1%. Cascade and Sacrifice also never fire below it, or below 1%. The SL has no deferral of its own and is floored at 1%. |
| **Substitution** (`miwSubstitutionEnabled`/`micSubstitutionEnabled`) | When no entry slot is free (maxPos or Share Cap reached), closes the worst-scoring held position (any strategy's, not only MIW/MIC's) and opens the best fresh candidate in its place, but only if the candidate's collapsed score beats the held position's *current* score by the **Substitution Margin**. A held MIW/MIC position's current score (`_miwLiveCompositeScore`/`_micLiveCompositeScore`) is recomputed live from its rolling-average criteria (see **Position Rolling Average**), so it's judged on where it has drifted to, not where it stood at entry. Each candidate is pre-flighted through the Force-Evaluate top-up and entry vetoes before anything is closed, and a blocked one falls through to the next. It requires Co-Qualifying Penalty (Permafrost/Ashfall); without it every score is 0 and Substitution never fires. |
| **Substitution Margin** (`miwSubstitutionMarginPct`/`micSubstitutionMarginPct`) | How much better the new candidate must score than the worst held position, as a % of base margin (minNotional ÷ leverage), before a swap happens. Prevents swapping on marginal score differences. |
| **Substitution Min Age** (`miwSubstitutionMinAgeMins`/`micSubstitutionMinAgeMins`, default 35) | Minimum minutes a position must be held before it becomes eligible to be substituted out. |
| **Deferment** (`miwDefermentEnabled`/`micDefermentEnabled`, default on) | A regime-proxy entry stop, set on the **Exit** tab below Substitution. It blocks every new entry while the Sample Scorer headline is below zero (the favored side's mean raw 1h move in the bot's favor), or while a clause is in effect: **Both Poles Red** or the **Relative Target** floor. The headline test needs Sample Scoring; the floor needs only the LPA window. Two or more active paths trigger Ejection (see **Deferment & Ejection** below). |
| **Both Poles Red** (`miwDeferBothRedEnabled`/`micDeferBothRedEnabled`, default off) | Sub-toggle, only shown while Deferment is on. Defers while any criterion has both its `+` and `-` pole in the red on the scorecard side the chart shows — no good pole left to enter on. A pole under Min Samples doesn't count. Counts as one path toward Ejection. |
| **Re-entry Block Mode** (`miwReentryBlockMode`/`micReentryBlockMode`) | Defaults to **Losers Only**, which lets a symbol that just closed in profit re-trigger immediately and blocks only a symbol that closed at a loss. **Winners + Losers** blocks a symbol from re-triggering for one bulk-ticker cooldown window (12h by default) after any close, win or loss. |
| **Auto Slots** (`miwAutoSlots`/`micAutoSlots`) | Replaces the manual slot list with a minimum-gate qualifier: a ticker qualifies once it satisfies at least **Minimum Criteria per Slot** non-excluded criteria — not a fixed-size combination. Every criterion the ticker actually satisfies is captured and scored, not just enough to clear the floor. See `_miwAutoQualify`/`_micAutoQualify`. |
| **Minimum Criteria per Slot** (`miwAutoSlotSize`/`micAutoSlotSize`) | The floor (1–6). At 1, a single true criterion qualifies the ticker — any others it happens to satisfy are still captured and scored. |
| **Exclude from Auto** (`miwAutoSlotExclude`/`micAutoSlotExclude`) | Criteria omitted from Auto's qualifying set entirely — never checked, never counted toward the minimum, never scored. | **Force-Evaluate General Criteria** (`miwForceGeneralCriteria`/`micForceGeneralCriteria`, on by default) | Auto mode only. A ticker can miss `fund`, `iol`/`ios` or `lta`/`lpa` simply because that cycle's capped sample hadn't reached it yet. When on, just before a ticker opens, the plugin (`_miwTopUpGeneralCriteria`/`_micTopUpGeneralCriteria`) re-checks those criteria with a forced per-symbol fetch, adds any that are newly true and recomputes the composite score. | **Pole Blocking** (`miwPoleBlockEnabled`/`micPoleBlockEnabled`, default on; `miwPoleBlockPct`/`micPoleBlockPct`, default **200**) | Entry-tab toggle with a Threshold % field, shown only while Sample Scoring is on. | **Sparsity** (`pfSparsePct`/`afSparsePct`, always on, no toggle; default **25**, config-only) | Entry candidates are ranked by how much sample data their criteria have: each matched pole's score is pulled toward zero when its sample count is small. LPA never blocks an entry: with Liquidation Surveillance on its poles fill only from liquidation events and are thin by nature, so it's skipped when picking the thinnest pole (its score still shrinks by sample count). A family the scorecard doesn't score at all is likewise skipped rather than read as an empty pole. Blocks count in the scan skip summary and log a `🪶 Sparsity` line. |

### Slots UI

**Manual mode**: click a slot to select it, then toggle criteria on/off in the picker row below. ✕ deletes the slot; `+` adds a new empty one. All six criteria are tiered — clicking one opens its gate picker (direction plus tier) rather than toggling a bare tag. A slot with no criteria in it never matches.

**Auto mode**: replaces the manual builder with a minimum-slider and an exclusion chip row. A ticker qualifies on at least the chosen minimum of non-excluded criteria — every criterion actually true is scored, not just enough to clear the floor. The hint under the slider states the current floor as "qualifies on any N of M secondary criteria."

The six criteria are independent signed tiers, so any subset can be true for the same ticker at once and each contributes to the qualifying count on its own.

## Permafrost / Ashfall Plugin

Permafrost targets PseudoWinter; Ashfall targets PseudoChaser. They provide two things: the **Extremity Scorer / Lukewarm Scoring** engine that decides which readings MIW/MIC may trade on, and the **cross-bot bus** that lets the two sides coordinate halts. The bots' own halt timers govern halts; the plugins only lift them (Mutual DDH Lift) or trigger them (Gains Continuation). The panel has two tabs, **CROSS** and **SCORE**, with the Danger Zone (Export / Import / Clear Profile / Clear Plugin State) below.

### Partner Feed

The Cross tab shows a scrollable **Partner Feed** listing the last 20 events the partner bot has broadcast: cascade/sacrifice triggers, DDH start/lift, gains-lock start/lift, and GC steps. Each row shows a kind-specific detail — position count and collective PnL for cascade/sacrifice, PnL and step number for GC, symbol for a rolling sacrifice — and a UTC timestamp, date-prefixed for anything not from today. Empty until the partner has broadcast at least one matching event.

Useful for diagnosing Mutual DDH Lift and GC: if the feed shows a partner `ddh-start` or `gc` step but no lift follows on this bot, the problem is on the receive side (freshness window, own-side toggle, read loop), not the trigger.

### Sample Chart

Below the Score tab's scoreboard is a per-ticker bar chart of the sample cycle history, scrollable through past cycles. Two header buttons step through the views **Vol → IO → L/S → Fund → LTA → LPA**, plus **Liq** while Liquidation Surveillance is on and **Fcst** while the Forecast Grader is on. Each button is labelled with the view it goes to, the order wraps at either end, and the view resets to Vol on reload. The chart only shows when at least one sample exists. Each cycle group is stamped with its sample time: click one to pin the summary and chips to that cycle, or click elsewhere to return to the latest.

- **Vol** / **IO**: the 24h-turnover and open-interest samples, with a **Total avg** (on Vol, the number `va` measures against; plus ticker count) above a **Batch avg**. No outlier cap.
- **L/S**: each sampled ticker's long/short skew, the net long minus short share of accounts from Bybit's long/short account ratio (−100 to +100%, positive = long-heavy), drawn up in green when long-heavy and down in red when short-heavy from a zero line, on a symmetric axis sized to 1.3× the 95th percentile of |value|. It has a **Total avg** and **Batch avg** like the other views and its **Tickers** pills are coloured by side. Only tickers whose batch carried the ratio appear (batches from before 2.36.0 carry none). It is the same long share IO/L and IO/S split open interest by.
- **Fund**: each sampled ticker's funding rate (%), signed, with a **Total avg** and **Batch avg** like Vol/IO. Funding rides in the sample records, read from each ticker's fresh fetch.
- **LTA** / **LPA**: signed views (turnover deviation %, 1h price change %) drawn up or down from a zero line, on a symmetric axis sized to 1.3× the 95th percentile of |value|. Only tickers with a candle reading in a cycle appear. The **Tickers** pills are coloured when that ticker's own 1h move went the bot's way (up on Chaser, down on Winter) and gray when it went against it, was exactly flat or has no reading, so on both views colour means favorable; the hover says favorable or unfavorable, and on LTA adds the 1h move. (The Vol, IO and Fund pills are coloured when at or above the batch average.)
- **Fcst** (while the Forecast Grader is on): forecast accuracy, batch by batch. Each column is one graded start batch (the last ten), with one bar per ticker (best first) for its accuracy, up from the **70%** line when at or above it and down when below (axis 0–100); the column is stamped with the time it was graded. After a dashed line come the batches still to come: a faint tick and the number of forecasts falling due in each (`+1` = the next batch). Click a graded column to select it (the latest is selected by default); hover shows its count and grade. The summary shows graded and pending counts, lead, revisit share and voids, a **Window** line (accuracy and influence) and a **Batch** line for the selected batch, and a **Tickers** pill opens a table of that batch's tickers, best accuracy first: accuracy % (green at 70% or above), projected pp, actual pp (green when the sign was called right) and the raw move, scrolling both ways. The Fcst view has no ticker chips.
- **Liq**: each watched ticker's liquidation lean in pp over the watch that started on that cycle, shown as a signed view from a zero line (up = liquidated shorts dominated, down = liquidated longs, zero = watched but quiet). A **Window avg liquidation lean** (each ticker's latest liquidation-event reading; watched-but-quiet tickers aren't counted, so they can't pull it toward 0) sits above the **Batch avg**, which also counts only tickers that had events. The **Tickers** pills list only tickers that had liquidation events in the displayed batch, and their style shows how one-sided the watch was and which side led: **favorable** (pure, the bot's side) has fill and outline, **mixed favorable** fill only, **mixed unfavorable** outline only, **unfavorable** neither. Mixed means the minority side holds more than **Mixed %** of the turnover (default 30%; a dead-even split counts as mixed unfavorable), and favorable is liquidated shorts on Chaser and liquidated longs on Winter. Hovering shows the short/long split and the ticker's window instability, a `!` marks tickers currently skipped for entry, and the summary line adds how many tickers are unstable. Watches from before the split was recorded only know which side led, so their pills show as pure. Only tickers watched in a cycle appear, and only cycles watched while Liquidation Surveillance was on carry it; the newest cycle fills in once its watch is scored on the next scan. It rides in the same cycle history as the other views, so it holds as many cycles as that history does.

### Extremity Scorer

Each criterion is a **dial family** (`fund`, `va`, `iol`, `ios`, `lta`, `lpa`) with a `+` and a `-` pole; under Sample Scoring `lpa` is the outcome and has no dial. Each scan's readings build per-pole cutoffs that sort every reading as extreme or lukewarm, and closed trades are tallied per side and per pole. The side that has earned more dollars becomes the favored side (ties default to extreme), and the Lukewarm Veto rejects candidates whose criteria mostly sit on the other side. Scorecards are per bot, each reflecting only its own trades; see **Extremity Scorer Internals** in Trivia.

**Scorecard chart**: only the favored side's chart is shown — Extreme or Lukewarm — and it flips automatically when the favored side changes. It is a single non-wrapping row of criterion duos that scales to its container: the left bar is the `+` pole, the right bar the `-` pole, profit rises above a zero line and loss hangs below it, and the criterion emoji sits underneath. The header shows the side's name and total; hover a bar for its PnL and W/L. Only shown when MIW/MIC (or Blind-Entry / Liquid-Diver) is loaded and enabled.

**CLEAR** wipes this bot's closed-record store, sample pool, Sample Scoring store and Forecast Grader store together (`__ew_pf_extremity_v1`/`__ew_pf_dialpool_v1`/`__ew_pf_sampleobs_v1`/`__ew_pf_fc_v1`, or the `af` set) — cutoffs included, never the partner's.

Under **Sample Scoring** the same chart is titled **Sample Scorer** and its bars are mean edge in pp, with liquidation outcomes blended in when Liquidation Surveillance is on (hover shows the average edge, ↑/↓ counts and n). A status line above it shows the scored-sample count. The LPA dial isn't drawn, since LPA is the price outcome, unless Liquidation Surveillance is on, when LPA is scored on liquidation outcomes and drawn. With Liquidation Surveillance on, the status line also shows the liquidation-sample count, the tickers on watch and how many are on the quiet graylist. With the Illiquidity Filter on, it also shows how many tickers are illiquid, how many have been measured and the slowest.

**Headline & gauge**: the header number is relative. It's the favored side's favorable share of raw 1h move, meaning the move in the bot's favor as a share of all raw move on that side, so 50% is even. A gauge under it is scaled to the best share recorded, and hovering shows the sample count, the mean in dollars on one base position and the relative edge. The per-criterion bars stay relative (mean edge vs the sampled population). Beneath the gauge, **bottom** and **peak** show the lowest and highest share recorded; they only update once the favored side has at least 10 raw samples (and at least Min Samples), and they're cleared with the samples. The headline reads `—` until enough samples carry a raw move. With Liquidation Surveillance on, the share and the dollar mean are the 50/50 mix of the price and liquidation values (hover shows how many liquidation samples went in), and **bottom** and **peak** record that mixed share.

The dollar mean and the share are always blended from the same figures, so they can never disagree in sign: each source (price, liquidation) is reduced to its mean favorable pp (P) and mean unfavorable pp (Q) per observation, the sources are mixed on P and Q, and the mean is P − Q while the share is (P − Q) / (P + Q). A share above 50% therefore always goes with a positive mean, and the colour follows both.

## Randomized Outcomes

Scan timing drifts independently per tab, and the sample is a fresh random draw of **Batch Size** candidates each cycle, so two identically configured instances won't share entry triggers, exit timing, or readings. This is intentional: instances in lockstep are easier to front-run and cluster losses at the same market event.

## Multiplex Plugins

To save resources in single-file browser execution, the system supports **Multiplex Plugins**. A standard plugin keeps its own telemetry isolated. A multiplex plugin instead hooks into the combined component built when all plugins are loaded, reading the core data arrays, batched API payloads and state structures directly, without wrapping or reassigning parent methods. This treats the master surveillance/execution engine as a shared database, which cuts resource use and avoids race conditions between plugins.

### The Speeder Module (Tentative Multiplex)

Located in `/plugins/multiplex/`, **Speeder** reuses functions in `MultiIndicator` and the data produced by `Ashfall/Permafrost`. That lets it read the rolling sample-cycle histories and the entry criteria builder directly.

* **What it does**: instead of judging order flow by fixed millisecond limits, Speeder splits the whole deduplicated pool of recent per-ticker trade intervals at the median on each scan.

* **How it does it**: to filter noise, landing in the fast or slow half isn't enough. A ticker's trade interval must also pass that half's own *mean*, which confirms a clear gap from baseline market speed.

* **When it acts**: like `MultiIndicator`, Speeder chooses its entry criteria (fast or slow) automatically, using a `base` setting tied to the liquidation regime. It can enter fast or slow tickers in hot or cold regimes.

* **When it doesn't**: if the surveillance plugins it depends on aren't in the combined component, Speeder logs a warning and stays inactive.

> **Note**: The Speeder strategy is tentative and lacks long-term historical validation; it remains isolated within the multiplex directory for demonstration purposes and architectural testing.

### Criteria Sampling Internals

- **Ticker Ranking**: each scan draws **Batch Size** tickers (default 50) at random and fetches their data fresh; that batch is the sample that feeds scoring. Entry candidates are ranked on every ticker's latest stored reading, however old, and each is refetched right before it opens, so any ticker the sample has reached can be picked. Refetches stop at one batch size per scan, since fetching all six criteria across 600+ tickers every 10-minute scan would be too heavy on computation and bandwidth; a larger batch size is an option if you have the resources. The batch isn't always purely random: with Liquidation Surveillance on, tickers that just had liquidations stay and quiet ones are replaced (see **Liquidation Surveillance** below), and with the Forecast Grader on, up to its **Revisits %** of the slots go to forecasts falling due (see **Forecast Grader** below), with the Illiquidity Filter on, tickers measured as illiquid are left out (see **Illiquidity Filter** below).

- **Tier gate**: every criterion computes an integer tier as `floor(value / step)` and compares it against N. `fund` truncates toward zero instead, so a tiny negative rate lands on `fund-0` (mirroring `fund+0`) rather than flooring to `fund-1`. Current step sizes show as read-only chips under **Tier Step Sizes** on the Fetch tab. The same tier is recorded on the position and used as the scorecard key, so `fund>40` and `fund+70` are different tiers and are scored separately.

- **Bare-form exception — `fund`**: in Auto mode, a criterion named without a `>`/`<` comparison normally still requires a nonzero tier. `fund`'s bare form is the exception: it matches any finite funding rate, exactly 0% included, because real Bybit funding rates mostly sit well under a single **Fund Step**. A near-zero rate is a real lukewarm reading (`fund+0`/`fund-0`), so it attaches and feeds the lukewarm chart. The tiered forms are unaffected.

- **Funding emoji**: position and trade badges show 🤑 or 💸 for a `fund` tier, and the emoji says whether that funding sign favors the bot's own direction, so Winter and Chaser show opposite emoji for the same raw sign. The Extremity Scorer's own pills use one fixed set on both bots (💸 positive, 🤑 negative).
- **`va`**: `va+12` = 12 tiers hotter than the sampled population. `_pfVolIoWindowAvg`/`_afVolIoWindowAvg` delegates to `_pfWindowStats`/`_afWindowStats`, a deduplicated latest-reading-per-symbol read (`vol`, `oi`, `oil`, `ois`, `ls`, `lta` or `lpa`) memoized per history state; the Sample Chart's Total avg draws from the same read.
- **`iol` / `ios`**: a ticker's long share of open interest is `oi × long share` and its short share `oi × (1 − long share)`. The long share is Bybit's long/short account ratio (`_pfLsRatio`/`_afLsRatio`: `GET /v5/market/account-ratio`, 5-minute period, latest row, `buyRatio ÷ (buyRatio + sellRatio)`), fetched per sampled ticker with the batch and stored on its sample record as `bl` (null when the call fails; the record then carries no `bl`). The tier is `floor(100 × ln(share ÷ window average) ÷ step)` against the window average of that share (`oil`/`ois` in `_…WindowStats`, which only counts latest readings that carry both `oi` and `bl`), so there is no tier without both, or without a window average. The **L/S** chart view and the batch context read the same `bl` (skew = `(2 × bl − 1) × 100`).
- **`fund`**: tier is `trunc(rate% / Fund Step)` with an explicit sign, so tiny negatives tag `fund-0` and exact zero tags `fund+0`. Sample records carry the funding rate as `fr` (%) so the Fund chart and Sample Scoring can use it.
- **`lta`**: `_pfLtaDev`/`_afLtaDev`; `lta+12` = 12 × **LTA Step** (default 10%) above the ticker's own average hour (`turnover24h / 24`). No population baseline.
- **`lpa`**: `_pfLpaWindowAvg(sym)`/`_afLpaWindowAvg(sym)`, in tiers of **LPA Step** (default 0.25pp). Absolute points, since a relative deviation is unstable near a zero mean. No tier until at least one other ticker has an `hc` reading in the window.
- **Candle fetch**: `_pfHourCandle`/`_afHourCandle` calls `GET /v5/market/kline` at `interval=5&limit=26` (130 minutes of 5-minute candles) and merges the candles inside the last completed hour (`_pfHourStart`) into its hour reading, so `ht`, `hc` and `htp` keep their meaning (a minute with no trade can leave the merged hour a little short); the forming candle is never part of it. The candles also sit in memory for the batch (`CAND5`), where the Forecast Grader reads the typical price of the last ~10 minutes (`_pfTyp10`/`_afTyp10`: the two newest candles started within 15 minutes of now, (highest high + lowest low + last close) / 3) and the path since a forecast. The hour reading goes in a memory-only per-symbol cache (`HOUR_CACHE`, pruned past 500) and is attached, as `ht`, `hc` and `htp`, to the ticker's OC cycle entry, so a **Follow Partner Bot** instance gets it from the leader (`_pfHourReading`/`_afHourReading`). The fetch rides the same batch (`wantHr` on `_ocFetchBatch`) whenever `lta` or `lpa` is in use.
- **Fresh batch fetch**: `_pfFetchFreshTicker`/`_afFetchFreshTicker` calls `GET /v5/market/tickers?category=linear&symbol=` per batch symbol, keeps the raw payload for the scan (`_pfFreshTicker`/`_afFreshTicker`) and stores a compact `{ vol, oi, fr, px, ch }` reading. A failed fetch drops the ticker; there is no fallback to the bulk list. A **Follow Partner Bot** instance rebuilds tickers from the leader's readings (`_pfSynthTicker`/`_afSynthTicker`). Entry candidates are refetched the same way by `_pfFetchCandidate`/`_afFetchCandidate` (ticker, plus OC and the hour candle when used), which touches neither the OC results nor the cycle history.
- **Entry-pool freshness**: MIW/MIC act once per new batch (`_pfOcResultsAt`/`_afOcResultsAt`), not once per bulk fetch, and `_miwOpen`/`_micOpen` skip the pre-open price refetch for a ticker from the current batch (`_pfTickerIsCurrent`/`_afTickerIsCurrent`). Candidates are ranked on each ticker's latest stored reading (`_pfLatestReadings`/`_afLatestReadings`, rebuilt by `_pfSynthStored`/`_afSynthStored` with `_cycle` set to that reading's own cycle time, so only the latest batch counts as current). Before a non-batch candidate opens or displaces a position, `_miwVerify`/`_micVerify` refetches it, reruns the slot match and veto with the dial-pool sample off, and stops at **Batch Size** refetches per scan. The refetched ticker only has to still qualify; it doesn't need to keep its ranked tier or score.
- `_miwHourTier`/`_micHourTier` returns `null` for missing data: the criterion check reads it as false and the annotator as "no sample", never a fake `+0`.
- Emoji for retired criteria stay resolvable in `critEmoji`/`afCritEmoji` so old records and exports render; they are display-only.

### Deferment & Ejection Internals

- **Deferment signal**: `_miwWeatherNeg`/`_micWeatherNeg` reads `_pfSampleWeather`/`_afSampleWeather(side)` on the favored side and defers while its dollar `value` is below zero, with no deadband, trim, or cooldown. It needs Sample Scoring and returns nothing until the scorecard has a headline.
- **Deferment effect**: the scan returns before every open path, with guards inside `_miwTrySubstitute`/`_micTrySubstitute` and `_miwOpen`/`_micOpen`. Historical scoring still runs. One `⛔ Deferment` log line per streak.
- **Ejection**: runs every scan ahead of slot logic (so it acts with no active slots) when the deferment state's `eject` is set, which needs two or more paths in `why`. `_miwEject`/`_micEject` closes every non-pending position of any strategy concurrently (`Promise.all`), each close in its own try/catch, with one `⏏️ Ejection` log line naming the paths and close reason `ejection`. Each trade is scored against its opening criteria.

### Relative Target & Scorecard Deferment Internals

- **Targets**: `_miwRelMoves`/`_micRelMoves` reads `_pfOcCycleHistory`/`_afOcCycleHistory`, takes the latest `…RelBatches` cycles by time and each ticker's latest `hc` (1h price change %) within them, and averages the positive and the negative readings separately; it returns null unless each side has at least Min Samples (floor 3) readings. `_miwTargets`/`_micTargets` turns that into the targets: the favorable side's average × `leverage` is `entryTp` and `cascadePct`, the other side's average × `leverage` (floor 1%) is `slPct` and `sacrificePct`. Chaser's favorable side is the positive average, Winter's the negative. It returns the configured values untouched (`active:false`) when Relative Target is off, neither Cascade nor Sacrifice is on, or `_…RelMoves` has no data. `_miwEffCascadePct`/`_micEffCascadePct` and `_miwEffSacrificePct`/`_micEffSacrificePct` return the resolved % floored at Min Entry TP and 1%; `_miwTargetsText`/`_micTargetsText` feed the Exit-tab readout. A saved `…TargetHalvingEnabled` is migrated to `…RelativeTargetEnabled` once at load.
- **Per-position overrides**: `_miwOpen`/`_micOpen` pass `_tpPct` and `_slPct` on the candidate. PseudoWinter/PseudoChaser use `_tpPct` for the entry TP, and `_slPct` for the binary-mode SL at open. It is also stored as `pos._slPctOverride`, which the DCA-mode SL arm, the SL drift check and the position card honor. Both candidate fields are excluded from the copy of candidate fields onto the position.
- **Deferment layering**: `_miwDefermentState`/`_micDefermentState` wraps `…DefermentStateBase`. The wrapper evaluates the negative-headline test (on with Deferment), Both Poles Red and the base on their own and merges them, with `why` listing those that hold and `eject` set when there are two or more. The base holds only the Relative Target floor test: it defers while the resolved entry TP is under Min Entry TP. `_miwWeatherNeg`/`_micWeatherNeg` and `_miwBothPolesRed`/`_micBothPolesRed` are the two clause tests; the latter reads the favored side of `pfLukewarmScoreboard`/`afLukewarmScoreboard`.
- **Headline source**: `_pfSampleBuild`/`_afSampleBuild` accumulates the raw edge per bucket into `pfSampleBucketMeans`/`afSampleBucketMeans` (`aE`/`aL`, counts `nAE`/`nAL`) and the signed favorable share `(P−Q)/(P+Q)` of those raw moves (`sE`/`sL`). `_pfSampleWeather`/`_afSampleWeather` returns the dollar `value`, the share (`s`, and `share` as 0–1) and the peak/bottom of each (`hi`/`lo`, `sHi`/`sLo`). `_pfSampleTrackWx`/`_afSampleTrackWx` keeps those peaks in the sample store as `wx`, and the leader shares them with followers. `aE`/`aL`/`sE`/`sL` come from one blend: each source is reduced to per-observation pp mass `{P, Q}` (price `p/n`, `q/n`; liquidation `p/w`, `q/w` once its bucket holds Min Samples), the sources are mixed on `P` and `Q` (50/50 for liquidation, only when the base exists), and `a = P − Q`, `s = (P − Q) / (P + Q)`, so their signs can't differ. With Liquidation Surveillance on, the liquidation side is part of that mix; `nlE`/`nlL` report its count, `nE`/`nL` and `nAE`/`nAL` include it, and the weather's `nl` carries it for the tooltip. The bucket `extreme`/`lukewarm` means that pick the favored side are mixed the same way. `aE0`/`aL0`/`sE0`/`sL0` are still published (the removed Silence Penalty and Silence Amplifier used to scale the headline), so the negative-headline Deferment test reads the mixed share and value directly. The peak/bottom `sHi`/`sLo` are still tracked for the gauge; Relative Target no longer reads them.

### Extremity Scorer Internals

- **Cutoffs**: come from the sample pool (`pfDialSamplePool`/`afDialSamplePool`), fed by `_pfDialSample`/`_afDialSample` on every criterion annotation, not only trades, and persisted across reloads. A pole with at least **Min Samples** readings cuts off at its **Extreme Split** percentile; a reading at or above it is extreme, anything below it and everything on an unproven pole is lukewarm. Bare sign-only tags from Blind-Entry/Liquid-Diver (`+fund`/`-fund`/`+ocs`/`-ocs`) carry no magnitude and always classify extreme.
- **Two tallies**: the dial tally counts extreme occurrences only and is the flat `micCollapsedSlotRanks`/`micCollapsedCritStats` lookup that Co-Qualifying Penalty and entry ordering read. The Lukewarm Scoring tally counts every occurrence, bucketed by class then by pole (`fund+`/`fund-`, not merged by family, since a family's poles are opposite signals).
- **Favored side**: `_pfLukewarmFavoredSide`/`_afLukewarmFavoredSide`, re-decided each time the scorer rebuilds (once per scan cycle).
- **Veto**: `_pfExtremityVeto`/`_afExtremityVeto` counts the share of a candidate's dial-eligible criteria on the non-favored side and vetoes at **Lukewarm Veto**%. An unproven dial counts against the candidate. It checks every entry.
- **Pole Blocking**: `_miwPoleBlocked`/`_micPoleBlocked`, called from `_miwIsEntryBlocked`/`_micIsEntryBlocked` after the Lukewarm Veto, so it covers both the entry-pool filter and the post-top-up re-check. Reads the favored side of `pfLukewarmScoreboard`/`afLukewarmScoreboard`; inert without Sample Scoring.
- **Position Rolling Average**: when on, `_pfPositionCriteriaSample`/`_afPositionCriteriaSample` re-reads each open position's locked criteria families every scan and keeps a rolling 24h average per family, using a fresh single-ticker fetch and the cached 1h candle for `lta`/`lpa`. These fetches are exempt from Leader/Follower's no-own-fetch rule, like Force-Evaluate's. `_pfPositionAvgCriteria`/`_afPositionAvgCriteria` rebuilds the tag from the average, falling back to the frozen entry tag (`_miwCriteria`/`_micCriteria`, or the Blind-Entry/Liquid-Diver equivalents) for any family under **Min Samples** readings. Close-time scoring, Extremity Re-Evaluation and Substitution's live score all read that average. When off, nothing is fetched and only frozen tags are used; the cutoff sample pool is unaffected either way.
- **Sample Scoring**: when on, `_pfExtremityBuild`/`_afExtremityBuild` returns `_pfSampleBuild`/`_afSampleBuild` instead of walking closed records. It publishes the same outputs (cutoffs, `micCollapsedSlotRanks`/`miwCollapsedSlotRanks`, the two-bucket scoreboard) from `__ew_*_sampleobs_v1`, plus the per-bucket mean edge (`pfSampleBucketMeans`/`afSampleBucketMeans`) for the favored side. `_pfSampleIngest`/`_afSampleIngest` runs with each new sample cycle and stores one observation per ticker: its criteria tags at sample time, `y` (the last completed hour's price change minus the rolling LPA average from `_pfLpaWindowAvg`/`_afLpaWindowAvg`) and `r` (the raw change). The build keeps only each ticker's latest observation per clock hour and skips `lpa` tags on price observations. The leader publishes `sampleScore` on the shared registry and a follower adopts it each scan (`_pfSampleAdopt`/`_afSampleAdopt`).
- **Forecast Grader**: `_pfFcPlan`/`_afFcPlan(pool, cap)` is called by `_miwScanFetch`/`_micScanFetch` before the batch is built (leader only, null when off or following). It takes the pending forecasts with `d <= seq + 1`, oldest first, skips illiquid tickers (`_pfIlqIs`/`_afIlqIs`), caps them at `floor(cap × share)` and stores `{seq, cap, rev}` in `_pfFcPlanned`/`_afFcPlanned`; the builder removes those symbols from the pool, passes `cap − revisits` to `_pfLiqPick`/`_afLiqPick`, and fetches `[...revisits, ...pool]` deduplicated and cut to `cap`. `_pfFcIngest`/`_afFcIngest` runs after each batch's `_pfSampleIngest`/`_afSampleIngest` (and for a seeded follower batch, where it returns at once since a follower adopts the store with `_pfFcAdopt`/`_afFcAdopt`). It is idempotent on the batch timestamp, increments `seq`, and (1) grades every forecast with `d <= seq` whose ticker is in the batch with a price: elapsed over 1.5 × lead × `_pfFcStepMs`/`_afFcStepMs` counts as `late`, a missing ticker is retried until `seq − d >= 2` and then counts as `gone`, and a start batch with under 3 gradable forecasts counts as `thin`; the move is `m = (typical / price − 1) × 100`, where typical is `_pfTyp10`/`_afTyp10` of the ticker's 5-minute candles from this batch's fetch (`CAND5`; else the revisit result's `htp`, else its `px`) and price is the frozen typical price, `mu`/`md` are the highest and lowest point of those candles since the forecast, and the actual is `y = m − k`, `k` being the cohort's mean `m`; `y`, `m` and `k` are stored raw. Each graded start batch also files its Range Fit entry (`_pfFcRangeAdd`/`_afFcRangeAdd`: the state kept in `fc.ctx[a]` and the quantiles of the cohort's `m − k`). Then (2) it starts forecasts from batch results that are not revisits and not already pending: `_pfSampleTags`/`_afSampleTags` (without LPA) gives the tags, `_pfFcParts`/`_afFcParts` the mean `pnl` (and each family's share `w`, stored raw like `e`) of the scoreboard entry (`afLukewarmScoreboard.extreme`/`.lukewarm`, picked by `afDialCutoffs`, needing Min Samples) of each tag's pole, multiplied by `_pfSampleDir`/`_afSampleDir` to store it raw. Candidates are shuffled and capped at `min(share slots, share slots × (lead + 3) − pending)`, so the revisit half and the fresh half balance. The picked forecasts go through `_pfFcRangeFit`/`_afFcRangeFit` before they are stored. The scoreboard used is the one built before this batch's observations, so a forecast never sees its own outcome. `_pfFcStats`/`_afFcStats` reads both values in the bot's favor (`dir × e`, `dir × y`) and returns n, Spearman rho (average ranks for ties), hit and base, the top/bottom fifth means and spread (n ≥ 20) the OLS slope, the mean accuracy (`_pfFcAcc`/`_afFcAcc` per forecast) and the influence shares (`_pfFcInfl`/`_afFcInfl`). `_pfFcChartSvg`/`_afFcChartSvg`, `_pfFcBreakdownHtml`/`_afFcBreakdownHtml`, `_pfFcSummaryText`/`_afFcSummaryText`, `_pfFcWindowText`/`_afFcWindowText` and `_pfFcBatchText`/`_afFcBatchText` draw the Fcst view; `_pfFcExport`/`_afFcExport` builds the Export file and Import restores `forecast.store` through `_pfFcSanitize`/`_afFcSanitize`. Nothing in `_pfSampleBuild`/`_afSampleBuild` reads the grader. **Range Fit**: `_pfFcRangeAdd(st, ys, k, ts, a)`/`_afFcRangeAdd` builds the entry (the state features in `FC_RANGE_FEATS`, the quantiles of `ys` at `FC_RANGE_P` = 0, .1, .25, .5, .75, .9, 1), merges it into the nearest same-lead entry within `…FcRangeSim` (`_…FcRangeDist`: the RMS of the gaps over at least 3 shared features, each scaled by `_…FcRangeScale`, the larger of 1.4826 × MAD and half the standard deviation across the store; merge weight 1 / (min(count, 6) + 1)) or appends it, and `_…FcRangeTrim` drops the oldest past `…FcRangeKeep`. `_…FcRangeExpect(state)` needs 8 same-lead entries with a distance, takes the nearest `round(√n)` of them (5–15) and averages their quantiles weighted `min(count, 6) / (distance + 0.15)`. `_…FcRangeFit(list, state)` sorts the new forecasts by raw `e`, gives tied values their middle rank, reads the expected range at plotting position `(rank + 0.5) / n` by linear interpolation between the stored quantiles, and sets `e0` to the raw `e` and `e` to `blend × fitted + (1 − blend) × raw`; `…FcRangeInfo` keeps the last fit for the hint and the Export. The state is `_…FcCtx(entry)`, the batch context. `_pfFcPass`/`_afFcPass` (70) is the chart's up/down split.
- **Graylist**: there are two lists. The quiet graylist `lgray` (symbol → time it was found quiet) sits in the sample store and is written and read only by `_pfLiqPick`/`_afLiqPick`; a quiet ticker is simply not picked for the batch until the pool runs short, and it stays a normal entry candidate. The Instability graylist blocks entries and isn't stored: `_pfInstabStats`/`_afInstabStats` (memoized per history state and a `_pfLiqVer`/`_afLiqVer` counter, since `lu`/`ld` are written onto cycles already in history) sums `lu`/`ld` per symbol over the retained cycles, needs `pfInstabMinWatches`/`afInstabMinWatches` (2, no UI) watches with liquidations, scores `1 − |U − D|/(U + D)`, and flags symbols at or above `avg × (1 + Instability %/100)`. `_pfGrayHas`/`_afGrayHas` (checked in `_miwScanFetch`/`_micScanFetch`, counted as `excluded.gray`) returns true for that set, for any ticker `_pfIlqIs`/`_afIlqIs` flags (Illiquidity Filter), plus the old time-based `st.gray` for a leader (`pfDistMins`/`afDistMins`; nothing writes it any more, and the status line that counted it is gone). The Instability check works while following, and neither of those two lists does anything when Sample Scoring or Liquidation Surveillance is off; the Illiquidity check depends only on its own toggle. `_pfLiqPillClass`/`_afLiqPillClass` classifies a watch for the pills from `lu`/`ld`, falling back to the sign of `lq` on older cycles.
- **Thin poles**: a pole under **Min Samples** scores 0 and counts as lukewarm; at Min Samples its score becomes the plain mean of those readings with no shrinkage, so a rare pole (e.g. `fund-`) jumps from neutral to full weight on a handful of readings. Entry ordering discounts thin poles separately (see **Sparsity**).
- **Score Horizon**: `_pfObsHorizonMs`/`_afObsHorizonMs` (the setting, minimum 0.5 h), `_pfObsLive`/`_afObsLive` (observations inside it) and `_pfObsTrim`/`_afObsTrim` (age trim, then a byte cap from `_pfObsCap`/`_afObsCap`) are the only retention rules for the sample store. `_pfSampleBuild`/`_afSampleBuild` and the status line read `_…ObsLive`, so scores follow the horizon between saves. The copy published for a following bot is the same age trim capped at 60 KB, so a follower can hold less than the leader.
- **Export / Import**: `_pfExportPart`/`_afExportPart` builds each export from the in-memory stores (cross events through `_…CrossRead`, so the full shared log, not the partner feed); `…ExportData` adds `exportType`, `exportedAt` and `version`. `_pfImportApply`/`_afImportApply` recognizes record types by their keys, not by `exportType`, which is why single-type files, Profile and Everything all import, and it replaces only the stores present in the file. Sample observations go through `_…SampleSave`, so anything older than the horizon is dropped on import; cross events are merged on `ts|kind|source|symbol` because that log is shared with the partner bot.
- **Liquidation Surveillance**: the feed is `allLiquidation.<symbol>` on the public linear WebSocket, held at module level in `LIQ`: the socket, its subscriptions, the per-symbol tally `{up, dn, n}` (up = liquidated-short turnover, down = liquidated-long turnover, `S:'Buy'` meaning a long was liquidated), the watched set and the closed watch awaiting scoring.
  - **Feed**: subscriptions are diffed and sent 10 per request, with a 20 s ping and 5 s reconnect (`_pfLiqWsSync`/`_afLiqWsSync`, `_pfLiqWsApply`/`_afLiqWsApply`), and only while `_pfLiqOn()`/`_afLiqOn()` holds (toggle on, Sample Scoring on, not following).
  - **Picking**: `_miwScanFetch`/`_micScanFetch` calls `_pfLiqPick(pool, cap)`/`_afLiqPick` with the shuffled pool. It closes the watch that just ran (snapshots and resets the tally; a watched ticker with events that is still in the pool is kept, most turnover first, and every watched ticker without events goes into `lgray`). It then fills the batch with the kept tickers, fresh non-graylisted ones and, only if still short, the oldest-graylisted (removed from `lgray` as they return), and subscribes the new set. It returns null when off or following, and the random batch stands.
  - **Ingest**: after that scan's batch lands, `_pfSampleIngest`/`_afSampleIngest` calls `_pfLiqIngest`/`_afLiqIngest`. It writes one `k:'l'` observation per ticker with events: criteria from the fresh reading (`_pfSampleTags` with LPA included), `y = (up − dn)/(up + dn)`, `r = y × S` and `w = up + dn`, where `S` (`_pfLiqScale`/`_afLiqScale`) is the median of |latest 1h change − window average| over each ticker's latest reading (floor 0.05pp). A ticker with events that wasn't re-fetched (more liquidated tickers than the batch holds) gets none.
  - **Cycle stamps and sharing**: it also stamps `lq` (the lean in pp, 0 for watched-but-quiet) and, for tickers with events, `lu`/`ld` (liquidated-short / liquidated-long turnover in $) on the cycle the watch began on. The Liq chart view reads `lq`, and the pills and Instability Graylist read `lu`/`ld`. The leader also publishes the lean on the shared registry as `liqLean` (`{cts, lq, ls}`, `ls` being the `lu`/`ld` split per symbol), keyed by the ts the cycle was published under (stamped on the cycle as `pub` after the `ocResults` write). A follower's `_pfLiqAdopt`/`_afLiqAdopt`, run at the end of `_ocSeedFromShared`, files it on the matching cycle of its own history, trying again next scan if that cycle isn't there yet.
  - **Build**: `_pfSampleBuild`/`_afSampleBuild` ignores `k:'l'` observations while the toggle is off. Otherwise each is parsed like a price observation (`edge = dir × r`, with `dir` −1 on Winter and +1 on Chaser), weighted `min(3, w / median w)`, added to the same pole pool and cutoffs and bucketed by them. The pole scores, favored-side means and headline figures are the 50/50 mixes described in **Headline source**.
  - **Caveat**: the LPA window average, V/A, IO/L and IO/S baselines read each ticker's latest reading, so a batch weighted toward tickers that keep liquidating tilts those baselines toward active names.
  - **Persistence**: the watch persists to `__af_liq_pending`/`__pf_liq_pending` (4 s throttle while events arrive, plus each pick, ingest and page hide). The first pick after a reload restores it (dropping anything older than 12 h), reconnects the feed, and the next ingest scores it like any other. Price and liquidation observations are trimmed to the byte cap separately (`_pfObsTrim`/`_afObsTrim`).
- **Illiquidity Filter**: readings live in the module-level `ILQ.rec` (`{ SYM: { t, g } }`), loaded by `_pfIlqLoad`/`_afIlqLoad` in `init()` and saved by `_pfIlqSave`/`_afIlqSave` to `__ew_pf_ilq_v1`/`__ew_af_ilq_v1`.
  - **Measure**: `_pfIlqMeasure`/`_afIlqMeasure(sym)` makes one `GET /v5/market/recent-trade?category=linear&symbol=…&limit=3` through `_qFetch`, sorts the trade times and returns `(newest − oldest) / 2` in ms. It returns null (nothing recorded, retried next batch) on a failed fetch or fewer than 3 trades. A reading is fresh while younger than `…IlqRefreshDays` (`_pfIlqFresh`/`_afIlqFresh`); `_pfIlqIs`/`_afIlqIs` is true when the toggle is on, the reading is fresh and its gap exceeds `…IlqSlowSecs` × 1000.
  - **In the batch**: in `_ocFetchBatch`, a ticker already flagged is skipped before any fetch. Otherwise, right after its ticker fetch and before the hour candle, a ticker with no fresh reading is measured; if that makes it illiquid it's removed from the batch (`FRESH_TICKERS` entry deleted, no candle fetched, no result). The batch log line adds `N t measured (M illiquid, left out)`. The save runs once per batch and drops readings unseen for 3× the refresh window.
  - **In the pool**: `_pfGrayHas`/`_afGrayHas` includes `_…IlqIs`, so MIW/MIC leave flagged tickers out of the scan pool before the batch is drawn, and they don't take a batch slot. Counted as `excluded.gray`.
  - **Following**: a follower makes no fetch. `_pfIlqAdopt`/`_afIlqAdopt`, run in `_ocSeedFromShared`, merges the leader's shared `ilq` (`{ SYM: [t, g] }`; the newer reading per ticker wins) into its own store and never publishes it back.
- **Stablecoin Filter**: verdicts live in the module-level `STB.rec` (`{ SYM: ms }`), loaded by `_pfStbLoad`/`_afStbLoad` and saved by `_pfStbSave`/`_afStbSave` to `__ew_pf_stb_v1`/`__ew_af_stb_v1`. It adds no request: `_pfHourCandle`/`_afHourCandle` calls `_pfStbJudge`/`_afStbJudge` with every freshly fetched hour candle, which takes the range of the candle's open, high, low and close and the current price (the forming candle's close) as `(max − min) ÷ open` and stamps the ticker when it is under `…StbMinPct`. `_pfStbIs`/`_afStbIs` is true while a stamp is younger than `…StbHours`. In `_ocFetchBatch` a ticker just judged a stablecoin is dropped from the batch after its candle fetch (no result), and `_pfGrayHas`/`_afGrayHas` includes `_…StbIs`, so MIW/MIC leave it out of the scan pool (counted as `excluded.gray`) until the verdict expires. A follower never judges: `_pfStbAdopt`/`_afStbAdopt` merges the leader's shared `stb`.
- **Sparsity**: `_pfPoleData`/`_afPoleData` returns the sample count behind the bucket a tier tag lands in (Extreme or Lukewarm, by the pole's cutoff) and the median count across that bucket type's poles, read from the scoreboard (so liquidation samples count). It returns `null` for a family with no scoreboard entry at all (LPA under Sample Scoring), so `_pfSparseOne`/`_afSparseOne` skips it instead of treating it as an empty pole. `_pfSparse`/`_afSparse` turns a candidate's tags into a factor (the thinnest pole's `n / (n + Min Samples)`) and a block flag (thinnest pole under the floor % of the median). LPA still feeds the factor but is skipped when choosing the thinnest pole for the block flag, since its poles fill from liquidation events only and sit far under the median by nature. MIW/MIC apply the per-pole factor in `_miwScaledRank`/`_micScaledRank`, multiply the Co-Qual-off richness sort by the candidate's factor, and check the block flag in `_miwIsEntryBlocked`/`_micIsEntryBlocked`, which covers the entry-pool filter and the post-top-up re-check. It's inert until a scoreboard exists.
- **Win/loss counts can appear high**: a criterion shared across many slots accumulates records from all of them, and the Sponge Quota caps per criterion, not per slot.

### Cross-Tab Data Pool

Both bots share market data via `localStorage.__ew_shared_v1` and `BroadcastChannel('ew_shared')`. Writes are last-write-wins per data type. Either bot operates normally solo — the registry is simply absent and all ladder checks fall through to normal fetches.

Each bot publishes its own open-symbol list to this registry on every position open/close, and once more per heartbeat as a safety net for close paths that bypass `pseudoClosePosition` (e.g. the gap-fill audit). A following bot (`lfFollowPartner` on, partner heartbeat fresh) checks the leader's list before opening and skips any ticker the leader already holds; the leader never checks its own publish. Since the check only runs while `_lfIsFollowing()` is true, it switches itself off the instant the leader's heartbeat goes stale, with no separate expiry logic on the position data.

Not every `BroadcastChannel('ew_shared')` message carries a `localStorage.__ew_shared_v1` write behind it, though most do (`_sharedWrite`/`_sharedMerge` post a change notification after writing). `registerSharedMessageHook` is the general subscription point either kind of push is dispatched through on the receiving end.

### Scan Scheduler Internals

- **Stages**: `runScan` calls `_scanPipeline(ctx)`, which runs the host's `tickers` stage, then each plugin stage in load order (`pf-post`/`af-post`, then `miw-`/`mic-` `prep`, `fetch`, `pool`, `entry`). Stages share `ctx`; a plugin appends `{ id, group, run }` to `_scanStageDefs` in `transform`, and a stage returning `false` skips the rest of its group. On a host without `_scanStageDefs` the plugin falls back to wrapping `runScan`.
- **Checkpoints**: loops call `if (this._scanDue()) await this._scanCp()`, which yields once `schedSliceMs` has elapsed (40 ms while the tab is hidden). The yield is a `MessageChannel` task rather than `setTimeout`, because a hidden tab clamps timers to 1 s or more.
- **Idle lane**: `_schIdle(key, fn)` queues one coalesced job per key (extremity rebuild, re-eval, sample-store saves), flushed when the pipeline ends; `_schIdleCancel(key)` drops it, which MIW/MIC's own rebuild uses to supersede Permafrost/Ashfall's.
- **Timing**: each scan logs one `[SCH]` line with total ms, yields, long-task count and per-stage ms. `ui.scanning` stays on through the plugin stages, so a batch that outlasts the scan interval makes the next scan skip. The extremity rebuild itself is still one synchronous call.
- Every background or bulk fetch (bulk tickers, market watch, and any loaded plugin's kline and sample batches) runs through a single per-bot scheduling queue (**Scan Scheduling** in Main Config) instead of firing all at once. This keeps the browser responsive with one bot open and workable with two. Execution-critical single-symbol calls (opening, closing and watching a position) bypass the queue so order execution is never delayed behind background scanning. The scan itself is a pipeline of named stages that hands control back to the browser after each time slice (**Slice Budget**), so position watching, clicks and timers run mid-scan instead of waiting for it to finish.
- **Running both bots**: When both are open simultaneously they automatically share bulk ticker fetches, kline caches, and sample batches to halve API load. Either bot works normally on its own when the other tab isn't open.

### Live-Mode Internals

- **The tab buttons always work**: every control from **Order type** down is locked while Config Lock is on (it locks automatically while the bot runs). Settings are saved in the bot's config, so they persist and travel with Export / Import. Keys use the `ew` prefix on EverWinter and `sc` on SunChaser.
- **Balance**: fetched automatically the moment a valid key/secret pair is saved in the credentials panel, not only at page load.
- **Symbol banning**: a symbol is banned for a week when Bybit reports it can't be traded, or when it's blocked until a trading agreement is signed (for example some leveraged or inverse instruments). Both cases need a manual fix on Bybit's side, so the ban is treated as long-term instead of retrying every cycle.
- **Post-bail re-check**: after a bail sweep (manual Danger Zone bail or an automatic Drawdown Throttle bail), the plugin queries the exchange directly for any position still open in its own direction (Sell for EverWinter, Buy for SunChaser) and force-flattens it with a reduce-only close that follows the **Close** tab settings (see below). This catches positions that failed to fully fill.
- **Exchange sync cadence** (v1.5.1): the full-book `GET /v5/position/list` sync runs once before and once after each scan loop, and nowhere else. It no longer fires after an SL/TP close, so exchange-native TP/SL fills and DCA fills are picked up at the next scan boundary, at most one Scan Interval later. Entries and closes still confirm their own fills with single-symbol `position/list` calls while they are in flight.
- **Concurrent group closes** (v1.5.2): a live close doesn't return until the position is flat, because `_scLimitClose`/`_ewLimitClose` reprice and retry against the exchange (poll 2 s, reprice every **Reprice interval**), so a sequential loop stacked those waits per position. Every multi-position close path now runs its closes under `Promise.all`: `bailAll` (host), Cascade, Sacrifice and Ejection (`_miwCheckCascade`/`_micCheckCascade`, `…CheckSacrifice`, `…Eject`) and Extremity Re-Evaluation (`_pfExtremityReEval`/`_afExtremityReEval`). Each close is isolated in its own try/catch, so one failed close no longer aborts the rest of the group. Signed requests from the in-flight closes still queue through `_scDelay`/`_ewDelay` (250 ms apart), so they interleave instead of bursting. Per-position state stays safe through the `_scClosing`/`_ewClosing` guard and the host's `_closingIds` set, which make a second close of the same position a no-op.
- **Close-record lookup** (Permafrost/Ashfall): the `pseudoClosePosition` wrapper finds the trade it just closed by position id (`closedTrades.find(x => x.id === pos.id)`, skipped if the record already existed before the call) rather than reading `closedTrades[0]`. With concurrent closes another position's record can be inserted while this one is still awaiting, so index 0 and list-length growth no longer identify the right trade. The record feeds Gains Continuation, the close-score settle and the MIW/MIC direction-awareness feedback.
- **Cycle re-entry guard** (v1.5.2): each close schedules a `runScheduledCycle` about 500 ms after it finishes. The host guards the scan itself with `_cycleRunning`, but not the plugin's pre- and post-scan `position/list` syncs, so N concurrent closes would have run N syncs. The plugin's `runScheduledCycle` wrapper now returns immediately while a cycle or an earlier wrapper call (`_cycleWrapBusy`) is in progress.
- **Pre-entry check**: before each entry the plugin asks the exchange for that one symbol and skips the entry if any position is already open on it, so a new order is never stacked on a position the bot isn't tracking.
- **DCA repair**: re-places missing DCA conditional orders, and runs only in the post-scan sync. It is skipped in binary mode, for positions with no DCA orders, and for positions opened in the last 2 minutes, because order status can lag a fresh placement and would trigger a duplicate.
- **Live position prices**: the base bot's watcher skips live positions, so the plugin prices them itself. It reads the host's WebSocket ticker when the host has one for the symbol; otherwise it makes one REST ticker call per symbol on a throttle: the **Price Poll Interval** base (default 5 s), doubling while price moves less than 0.1% and capped at 60 s. This replaces a REST call per position on every 5 s tick.

### Plugin Transform Pipeline

```
pw()  →  plugin[0].transform(def)  →  plugin[1].transform(def)  →  ...  →  Alpine
```

Each plugin's `transform(def)` receives and returns the component definition, so load order matters for method wrapping. Strategy plugins must declare `after: ['everwinter']` / `after: ['sunchaser']` so the live-trading plugin's wraps are innermost, which means live-trading plugins (EverWinter, SunChaser) must load before strategy plugins (MultiIndicator, Permafrost/Ashfall). The Plugin Manager shows the current load order and warns about conflicts.

### Bybit API Endpoints Used

**Public**: `GET /v5/market/tickers` (bulk for the symbol universe, per symbol for criteria data), `GET /v5/market/recent-trade`, `GET /v5/market/kline` (hourly bars on the bots, 5-minute bars on Permafrost/Ashfall), `GET /v5/market/account-ratio` (long/short account ratio, Permafrost/Ashfall only), `GET /v5/market/instruments-info`. **WebSocket**: `wss://stream.bybit.com/v5/public/linear` (position price stream). **Signed (live mode)**: `GET /v5/account/wallet-balance`, `GET /v5/position/list`, `GET /v5/position/closed-pnl`, `GET /v5/order/realtime`, `POST /v5/order/create`, `POST /v5/position/trading-stop`, `POST /v5/order/cancel`, plus `GET /v5/execution/list` on the Psycho bots (DCA/AMa ladder fill checks). Signing: HMAC-SHA-256 via `crypto.subtle.sign`; 250ms minimum gap between signed requests (plugins).

**Call cadence**: the full-book `position/list` runs only before and after each scan loop. Single-symbol `position/list` calls happen around an entry (once before it, then polling for the fill) and while a close is repricing. On the Psycho bots, `execution/list` is called for a pending DCA/AMa stage only once price has reached that stage's trigger, plus one sweep of every pending stage after each scan loop to catch a wick through a trigger.
